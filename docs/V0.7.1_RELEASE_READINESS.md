# LinkBeacon v0.7.1 Release Readiness

Audit date: 2026-09-20 (Asia/Shanghai)

## Executive Summary

LinkBeacon v0.7.1 is in **RC Preparation**. The Device Center Polish + Port Scan
scope is feature-complete and frozen. Automated gates, signing verification,
artifact identity, and 16 KB compatibility are recorded below. Public release
still requires the separately authorized representative full regression using
the exact frozen signed RC1 artifact.

## Formal Scope

- Unified editing of Custom Name, Device Type, and Notes.
- Read-only Local Profile summary, atomic save, and dirty-state Back handling.
- Port Scan from Tools and Device Detail.
- Audited 24-port Quick Scan and inclusive custom ranges within `1..65535`.
- Bounded, cancellable TCP Connect scanning with network-change protection.
- Real progress, Stop, partial-result retention, open-port presentation,
  aggregate non-open results, and common-service hints.
- English and Simplified-Chinese presentation.

The frozen scope excludes SSL/TLS, Website Diagnostics, Wi-Fi Analyzer, UDP or
SYN scanning, banner grabbing, service fingerprinting, Port Scan History,
Report integration, IPv6 Port Scan, and background scanning.

## Feature Complete Evidence

The dedicated device-profile editor, shared Port Scan Core, bilingual Tools and
Device Detail integration, performance calibration, and Android 12 real-device
regression were completed before RC preparation. This task changes version
metadata and release documentation only; it adds no new runtime feature.

## Device Edit

Custom Name, Device Type, and Notes use one ViewModel-owned draft and one atomic
repository operation. Favorite, Wake-on-LAN, identity evidence, First Seen, and
Last Seen are outside that draft. Unsaved Back requires confirmation.

## Port Scan Core

- Final bounded concurrency: 64 workers; hard cap 64.
- Port Scan connect timeout: 1000 ms.
- Existing single Port Check default timeout: 3000 ms.
- Result categories remain OPEN, CLOSED, TIMEOUT, UNREACHABLE, and ERROR.
- TIMEOUT and UNREACHABLE may share a user-facing no-response aggregate, while
  the Core retains distinct typed counts.
- Common-service labels are hints only and never service or device-type proof.

## Port Scan UI

One Activity-scoped Hilt ViewModel and one screen serve Tools and Device Detail.
Neither entry auto-starts. Only confirmed open ports receive result rows;
non-open outcomes remain aggregate counters. Caller-aware Back and last-observed
address confirmation retain the existing navigation and identity boundaries.

## Performance

Android 12 performance validation covered Quick Scan and inclusive ranges
`1..100`, `1..1024`, `1..10000`, and `1..65535`, plus concurrency 16/32/64 and
timeouts 500/1000/1500. The selected final configuration is 64 workers and a
1000 ms connect timeout. The full refused-heavy range completed in about 77.8
seconds, retained six sorted unique open ports, and returned active sockets and
file descriptors near baseline.

## Cancellation

Stop cancels the producer and workers, closes registered active sockets, rejects
late generation results, and preserves only confirmed partial results. Back
offers Keep scanning or Stop and leave; it does not silently leave work running.

## Network Change

A material network fingerprint change terminates the session through the same
socket-cleanup path and returns NETWORK_CHANGED. Results from different network
contexts are not combined.

## Data Boundaries

Port Scan writes no History and does not enter Automatic Diagnosis or Reports.
It does not update First Seen, Last Seen, profile identity, MAC, UDN, Favorite,
Custom Name, Notes, Device Type, or Wake-on-LAN configuration.

## Internationalization

Port Scan and the unified profile editor ship with English and Simplified-
Chinese resources. User-entered targets, Custom Names, Notes, addresses, and
observed metadata remain verbatim.
