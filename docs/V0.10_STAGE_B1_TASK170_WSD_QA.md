## Protocol choice and limits

Primary references reviewed:

- [Microsoft WS-Discovery compliance](https://learn.microsoft.com/en-us/windows/win32/wsdapi/ws-discovery-specification-compliance): SOAP/UDP discovery and bounded envelope handling.
- [Microsoft MS-PBSD namespaces](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-pbsd/f02386d8-6c3b-4d4c-9f3b-bc38385fe26c): namespace URIs, not literal prefix names, identify the fields.
- [MS-PBSD computer information, section 2.2](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-pbsd/a3c6b665-a44e-41d5-98ec-d70c188378e4): host-level Computer type and computer/workgroup/domain information.
- [Microsoft WSD metadata Get](https://learn.microsoft.com/en-us/windows/win32/wsdapi/get--metadata-exchange--http-request-and-message): WS-Transfer POST to the advertised endpoint.
- [PnP-X categories](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/fundisc/pnp-x-provider-pkeys): the exact Computers category value.

One untyped WS-Discovery 2005/04 Probe, SOAP 1.2 / WS-Addressing 2004/08, is sent
to the standard IPv4 link-local multicast endpoint with TTL 1. This multicast
can be received by other devices on the same link; it is **not** a three-IP-only
send. Only the privately authorized T05/T06/T09 source addresses are admitted.
No periodic discovery, retransmission, alternate version, Resolve or port scan
is added. This deliberately omits the usual retransmission algorithm to obey
the maintainer's one-datagram limit. No response is not evidence of absence.

The persisted `task170-wsd-once` marker is committed before the first send
attempt. It survives Stop, Rescan, activity/process recreation and in-place QA
installation; no reset control is exposed or exercised. A failed send consumes
the attempt. A spent budget returns without opening a WSD socket. The existing
QA package is retained so no replacement formal application or new installation
identity is needed. WSD is enabled only by the private Task 170 asset in an
explicit `-PrecognitionQa -PwsdQa` Debug build.

## Network, parser and association boundaries

- Captured active Network must be Wi-Fi, non-VPN, on the authorized private /24;
  context and LinkProperties IPv4/prefix must agree, with an actual multicast
  interface. The existing Network Lease and generation gate are checked before
  I/O and before accepting results. An unsuitable environment is Not Tested.
- One network-bound multicast socket, ephemeral local port, no group membership;
  replies are unicast. The new stage shares Task 168's fixed two-thread pool and
  never changes process-wide network binding. No new permission is needed.
- Receive window 3,000 ms, at most 128 datagrams, 32 KiB per admitted response.
  Foreign source addresses/ports are discarded before parsing or raw logging.
- ProbeMatches must use the chosen namespaces, expected Action/RelatesTo/To,
  valid message ID and endpoint UUID. A source with conflicting endpoints, or an
  endpoint claimed by two admitted sources, supplies no accepted category/name.
- Metadata: at most one POST per admitted target, only an advertised literal
  source IPv4 HTTP address on port 5357. No DNS lookup, credentials, query,
  fragment, escaping, path traversal, alternative port, external host or redirect.
  Unsupported XAddrs are recorded as rejected, not silently retried.
- HTTP connection timeout 500 ms, total connect/read deadline 2,000 ms per
  target; no proxy, cookies, authentication or automatic retry. Only status 200
  and bounded uncompressed XML framing are accepted; headers cap at 16 KiB and
  XML at 64 KiB. Content-Length/chunked/close-delimited framing is bounded.
- XML: UTF-8, namespace aware, no DTD/entity declarations, rejecting external
  entity resolver, no schema/XInclude/resource fetching; depth 24, nodes 512,
  text per node 4,096. MetadataReference URLs are never followed.
- Metadata requires matching WS-Transfer correlation and host-level endpoint
  UUID. Only typed host Computer and ThisModel PnP-X Computers evidence is used;
  Hosted services, keywords, model/manufacturer strings and open ports are not
  computer classification. Contradictory explicit categories do not win by order.

This is an intentionally narrow Windows-compatible subset, not a general DPWS
client. HTTPS, other ports, non-literal XAddrs, alternate protocol versions,
positive hostile-responder interoperability and signed/authenticated WSD are
not claimed. No retry/variant experiment is authorized after a zero-gain result.

## Category and display behavior

Reuse `QaCategoryResult`, `QaCategoryMapper` and the Task 169 list/detail rows.
Valid WSD Computer type/self-report can add Computer / Confirmed, explicitly
labelled `reported`; Confirmed is **not authenticated physical hardware**. A
compatible NBSTAT candidate remains a distinct reason, not another discovered
device. With no WSD evidence the Task 169 result stays unchanged. T06 SSH alone
remains a service observation, not Linux/server category evidence.

WSD computer names are accepted only from the correlated host publication field;
domain/workgroup is not used for classification. Names are separate from category
and service. Custom and baseline names win, conflicting new names stay in details.
Manual category priority remains unchanged. No profile/history/identity/online
evidence, First Seen, Last Seen, saved name/type or Room schema is written.

Across both scanners this is **one unique device** gaining an independent

same remote source, not three independent authenticated identities. Inventory is
only the post-hoc truth comparison. No claim of Windows/Linux or server hardware
is made from these observations. T03 is outside Task 170's remote cohort on both
systems, so removing it from Android 16's denominator is not an identification
gain versus Task 169.

The accepted Android 16 publication-name field uses `/Workgroup:`; the initial
parser covered the documented `\Workgroup:` spelling and left this name empty.
The final parser accepts both explicit field formats. The received packet is
replayed **offline**, without another Probe/Get. Its name agrees with the already
known NBSTAT name, so it adds a source but **zero newly named devices**. Original
live JSON and the Android 12 timeout are preserved, not rewritten as new live
successes. The final APK differs from the live-capture APK only in this name
decoder and its offline tests; transport/category rules are unchanged. No
different protocol version or additional network experiment was performed.

### Time and resource cost

| Measurement | Android 12 | Android 16 |
| --- | ---: | ---: |
| C0 baseline | 4,227 ms | 4,097 ms |
| Existing Task 168/169 pipeline before WSD | 5,852 ms | 5,499 ms |
| WSD stage | **5,064 ms** | **3,677 ms** |
| Complete comparison round | 10,930 ms | 9,181 ms |

Per device, the new request budget was one shared multicast datagram plus one
metadata attempt; no metadata attempt targeted T05/T06 or an outsider. A request
counter denotes an attempted operation, not guaranteed remote receipt. Android
16 has an accepted response; Android 12's timeout is not overstated as a
successful metadata exchange. Timing includes the receive window and metadata
wait. Compare pre-/post-WSD within the same round, not different target counts
or network conditions from earlier tasks.

The stage uses one shared-pool worker; the existing pool stays bounded to two
threads. At completion/Stop/invalidation: registered resources 0, owner Network
Lease invalid/closed, C0 owner cleared. Device tests wait for active worker count
0 and empty queue, with pool size at most 2. Idle process-lifetime pool threads
are intentional, not leaked per-scan threads. No new CPU/memory benchmark is
claimed. No runtime scan/cancellation behavior is changed in the ordinary app.

## Maintainer conclusions

A. **T09: yes**, independent WSD Computer self-report supports upgrading the
existing NBSTAT candidate to a qualified self-reported category. No new host is
discovered by this classification.

B. **T05: no gain**. It remains Unknown. No retry, host reconfiguration, SMB
authentication, alternate discovery variant or extra port scan was attempted.

C. **T06: no new category**. SSH/OpenSSH remains service information only.

D. This is not a zero-gain WSD experiment overall, but the gain is narrow and
costs about 3.7–5.1 seconds in this sequential QA. Stop the experiment here.
Do not automatically enable WSD or pursue variants to force T05/T06 results.
Any later production decision needs separate review of multicast cost, explicit
self-report trust wording, bounded scheduling and unresolved interoperability.

E. Task 168 NBSTAT names and SSH service evidence, plus Task 169's clearly
qualified computer candidate, remain worthwhile narrow production-mapper review
items. Preserve user precedence, typed provenance, current-session ownership and
no automatic durable identity/category writes. PTR/reverse-mDNS and broad
computer/server/OS heuristics do not gain new validation from Task 170.
