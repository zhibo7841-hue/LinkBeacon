## Offline resource-pressure fixtures

B1ResourcePressureTest exercises the **production** AndroidLanHostEnricher session
admission and private generic I/O scheduler via test-only reflection, avoiding new
production test hooks. The test never executes inspect() for an offered host:
workers are held until cancelled. Generic I/O is separately exercised with mixed
unconnected UDP/TCP sockets and synthetic timeout/blocking functions. It reads the
current Android network identity locally for the guard; no datagrams, connects,
DNS requests, multicast, authentication or actual scan traffic are performed.
Both protocol-attempt counters remain zero. No copied scheduler is being tested.

| Simulated hosts on each phone | Queued while host workers deliberately held | Deferred/skipped |
|---:|---:|---:|
| 10 | 10 | 0 |
| 64 | 32 | 32 |
| 128 | 32 | 96 |
| 254 | 32 | 222 |

Offering the same host twice does not increase admission. These counts describe a
worst burst with zero active host consumers, not normal throughput or 254 actual
online devices. The separate direct-I/O harness stresses executor rejection as
well as timeout; its artificially numerous submitter coroutines are test code,
not how production's two host workers schedule protocol work.

On both phones at all four scales: physical I/O peak=2, executor queue<=32,
no-response/rejection completes with null, all sockets close, active I/O/resources
return to zero, and C0 physical work stays zero. Both existing socket types are
covered without increasing production budgets. An old uncooperative fixture worker
holds its physical slot through invalidation/close; a new session cannot replace it
to exceed two. Queued new work is cancelled before starting. Repeated Stop is safe.
The unchanged owner deadline closed blocked fixture I/O in 2008 ms / 2014 ms.
Process-lifetime idle pool threads intentionally remain; per-session jobs/queue/
resources are cancelled/closed. This validates scheduler/resource boundaries, not
254 end-to-end live NBSTAT and SSH transactions or CPU/heap performance.

Actual Wi-Fi-loss cancellation and live silent-target behavior reuse Task172's
Android12/16 evidence; Task174's network invalidation is simulated. No additional
household scan or forced network change was performed. Original counts, software
observations and 19.361->19.366 s / 19.069->19.058 s samples remain historical
measurements, not a claimed speed gain or new acceptance of a different APK.
