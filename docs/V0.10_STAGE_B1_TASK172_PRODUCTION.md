## Production changes

- Shared parsers moved to `feature/lanscan/.../domain/recognition/`: NbstatProtocol,
  NbstatExchange and SshIdentification. Existing packages/callers retained. Production
  and QA use one parser per protocol. NBSTAT RR_NAME/question/TTL=0/source/ID/port,
  bounds/conflict validation stays intact; UNIT_ID never becomes persistent identity.
- DeviceCategory extracts Task171's rules into the feature; QaCategory now delegates
  via aliases/evidence adapter. No second classifier. Confirmed means explicit
  self-report, not authentication. NBSTAT gives Possible Computer; SSH only service.
  Conflicts remain Unknown; repeated weak evidence does not become Confirmed.
- NetworkModule injects AndroidLanHostEnricher through LanHostEnricher into the
  existing LanScannerViewModel. Discovered devices are published before enrichment
  admission. Only current discovered remote devices qualify; scanner excluded.
  NBSTAT rechecks lack of an automatic identity name immediately before sending.
- Independent process-wide physical executor: 2 workers, queue 32. Session: 2 workers,
  channel 32, maximum 254 admitted hosts. Queue-full hosts are deferred/dropped for
  this round, never retried or stored in an unbounded pending list. Existing C0
  system resolver limits remain 4 / 32 / 254 / 1500 ms / 15 s.
- Once per host/protocol: unicast UDP137, 500 ms; TCP22 connect 250 ms plus absolute
  600 ms bounded initial-identification read. No authentication, writes or retries.
  Discovery closes TCP sockets, so an OPEN observation cannot provide a readable
  stream. SSH makes one necessary connection, without a preliminary port check.
- Captured Android Network binding, lease revalidation, generation/fingerprint/time
  checks reject stale observations. Stop/rescan/network invalidation close sockets
  and remove queued tasks. Physical workers cannot be replaced to bypass the cap.
  Two idle executor threads intentionally live for the process, not per session.
- Completed discovery does not wait for these protocols. Remaining work has a
  two-second tail cutoff. Existing mDNS/UPnP/C0 boundaries remain. No WSD default.

## Evidence, presentation and persistence

LanHostRecognition is transient session data attached to LanDevice. Mapper emits
separate typed NBSTAT name and SSH service observations with source/time, and uses
shared category rules. Existing brand/model/platform/vendor evidence is preserved.
Lists/Device Center use NBSTAT as a fallback; manual name/type wins. Detail reuses
its existing evidence section for qualified category and SSH software/source/time.
No new page or overall redesign. SSH is never a hostname/model/OS conclusion.

New facts do not enter identity aggregation/matching and their callback does not
trigger saved-profile observation persistence. Room/History schema, freeze point,
First/Last Seen, favorites, notes, manual fields and WoL contracts are unchanged.

Full runs rescan a QA-only saved profile: manual name/type, notes, favorite, WoL and
First Seen persist; old History JSON stays frozen, one record per completed scan;
Last Seen stops changing after settlement. No real user profile was edited.

Both systems pass Stop and actual Wi-Fi disable invalidation, with Wi-Fi restored
in finally. Zero new active I/O/resources at settlement; no new system/protocol calls
in the following two-second assertion window; no completed History. JVM tests cover
old generation/network/time rejection and rescan isolation. Android12's first network
test failed UI access due to screen lock; failure evidence retained, rerun after
maintainer unlock passed. Do not count the failed attempt as a passing run.

After close, C0 active/shared physical counts are zero. ViewModel retains lease/session
ownership; no second lease/network callback added. Baseline/integrated process FD
sample peaks: 177/178 (API31), 228/232 (API36); thread peaks 79/83 and 82/83. Counts
include Compose/test infrastructure, not isolated protocol cost. New protocol peak
I/O is 2 and settled socket count 0. CPU/heap and 254-responsive-host saturation
benchmarks were not performed. Idle process-wide worker retention is intentional.

## Remaining limits and candidates only

No response cannot classify a device or prove it offline. Silent devices/mobile/
hardware model coverage remains incomplete. Bursts can exhaust the bounded queue
and skip enrichment; discovery remains independent. Future separately scoped work
may improve source-qualified model presentation and evidence-section readability,
with broader representative-device tests first. WSD default, SMB/HTTP fingerprints,
new PTR/mDNS, model databases, authentication/terminal and cloud were not started.
