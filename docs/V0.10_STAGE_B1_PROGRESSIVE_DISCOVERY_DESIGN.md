### 1.3 新设计不能继承的强假设

1. `LanNetworkFingerprint` 在合格 LAN 上复用 Saved Profile 的 `LanNetworkScope`。
   同前缀、网关、接口、DNS，且 SSID 缺失/相同的不同网络可能得到同值；
   它没有 Android Network handle。**不能保证所有同前缀换网都被它单独识别。**
2. `AndroidLanNetworkBindingProvider` 是 WoL 用途，会主动选择物理 LAN 而绕开 active VPN；
   不可直接用作新名称查询的 VPN 绕行方案。
3. 现有 DNS v2 的 `DnsRecordType` 只有 A/AAAA/CNAME/MX/TXT；transport 每次读取 activeNetwork。
   不能不经适配就声称它已支持 PTR、指定 DNS 或绑定整个扫描的捕获网络。
4. SSDP 响应列表和 NSD 等待实例没有总数量硬 cap；HTTP read timeout 不是总绝对截止。
   现有四秒 mDNS 窗口也不等于所有补充任务四秒内物理退出。

## 2. 已确认方向与 C0 / C1 边界

| 方案 | 发现与名称关系 | 决策 |
| --- | --- | --- |
| A：全范围后补名 | IP 可渐进显示，名字等待整个地址阶段 | 保留为同环境基线；当前源码属于这一类 |
| B：每主机任务交错 | 名称占用该发现 worker，慢 resolver 降低后续发现吞吐 | 不推荐作为目标架构 |
| C0：独立有界单机队列 | 合格发现先显示 IP，再排名称；共享源时机不变 | 已确认优先设计，具体参数待评审 |
| C1：共享服务窗口提前 | 还需处理早到服务、尾部覆盖与额外请求 | 独立门槛，未实施、未选择窗口 |

C0 首切片只用现有系统反解来源，与基线使用相同目标集合和逻辑请求数。
调度改善首先是缩短有名样本的等待，不保证产生更多有效名。
三项新来源实验另做，每次只变一个因素。C0 不等于 Stage C 产品研究，
也不自动替代 B1.2 资源安全或 B1.3 实物验收。

```text
开始扫描 / 捕获 generation + 网络 lease
  ├─ 原发现引擎（32 worker，规则不变）
  │    └─ 合格 Host + 进度 ──非阻塞──> Session Reducer
  │                                      ├─ IP 先显示
  │                                      └─ Pending 表 → ready queue → 名称池
  │                                                        │             │
  │                                                        └─ 有界结果 ──┘
  └─ 原 UseCase 地址完成 → 原 History 冻结/保存点 → 返回完成会话
                           → 原Completed接纳/原资料同步 → 原共享 mDNS / SSDP 各一次
                                               → 同一个 Reducer
Reducer → revision 一致的视图快照 → 原列表 / 详情（一个识别 Mapper）
```

保留的锚点是 **UseCase 完成返回、VM接纳Completed并走完原资料同步门后**，而非仅看到
最后一个 SCANNING 更新：引擎先发 COMPLETED update，UseCase 写 History、返回 VM，
VM先发布Completed，再 await `syncFavoritesWithDevices`，然后才启动共享源。
记 `Td` 为地址发现结束，`Ta` 为走完上述原有门的共享源启动点；共享窗口仍从 `Ta` 起，
不因 PTR 队列未清空而等待，也不提前到首个主机。保存失败按现有错误路径处理，
单列地址结果/保存错误；不假称 History 成功或悄悄增加自动重试。另须覆盖原资料同步
异常导致共享源未启动的路径，不能把已发布Completed等同于NSD/SSDP已经开始。

## 3. C0 会话、事件与归并契约

以下原架构类型是设计示意；C0.1 的实际纯逻辑 API 对照见 3.4。

### 3.1 唯一会话 owner

一个 foreground `ProgressiveLanSessionCoordinator` 拥有串行 reducer。
transport 只回传事实；VM 转换为现有 UI，Composable 不启动查询。
核心 token 为 `(generation, capturedNetworkLeaseId, fingerprint, policyRevision)`：

- generation 由现有扫描 owner 分配；不混用引擎自增 ID 与 VM ID。
- lease 是 Android adapter 持有的实际 Network 与捕获接口/路由的临时引用；
  通过 onLost/onAvailable 及 DNS/Private DNS/VPN 策略变化使其失效。
  补充这一瞬时边界，不修改 Saved Profile 的持久 scope 或身份算法。
- 每次发包前与结果归并前都核对 lease/token；未知归属则跳过/中止，不自动找另一网络。
  API 31 NSD 无完整 Network 证据时仍如实标局限，不以应用附加标签充当系统证明。
- 保存 `baseDiscovery` 与 `evidenceByHost`，物化展示时合并。
  不再让发现整快照直接覆盖已经取得的名称。

新名称事实建议用独立 transient `NameObservation`：token、jobId、target IP、source、
queryName/type、候选名称、可得的TTL/到期时刻、observedAt、resolver路径/配置服务器、
缓存状态（CURRENT_RESPONSE / CACHE_OR_UNKNOWN）、hostRevision。实际响应者仅在transport
能证明时另列；不把configured DNS当它。SYS_REVERSE、SYSTEM_PTR、LAN_DNS_PTR、
MDNS_REVERSE_PTR、NBSTAT须可区分，不把反查名伪造为DNS-SD服务。现有 source enum仅有
REVERSE_DNS/MDNS/UPNP；这些细分标识、模型和主标题映射是后续实验/default采用门，
不是本轮已有字段。SYS反解只有调用完成时间，不能补造PTR报文观察时间或TTL；
`observedAt`仅在可证明对应观察/报文时填写，完成/接收时刻和缓存不明状态分开。
观察只限会话，不引入持久ID，不把名称、TTL或来源当匹配键。

### 3.2 字段所有权与事件

| 事件（均带 token） | 只允许修改 | 重要约束 |
| --- | --- | --- |
| `DiscoveryFrame(seq, rawUpdate)` / `HostAdmitted` | 已发现 IP、角色、探针正证据、discovery lastSeen、计数 | 由原发现流产生；新名字不能创建 HostAdmitted |
| `NameScheduled / NameStarted(jobId, ip, source)` | 对应任务与源状态、排队时间 | 每 `(token,IP,source)` 正常最多一次；不重试循环 |
| `NameObserved(jobId, candidates, provenance)` | 该源的有界自动名称与观察 revision | 不动发现证据、时间、用户字段或其他源；保留别名/冲突 |
| `NameSettled(outcome)` | NoData/Failed/TimedOut/Cancelled 等状态 | 无数据仅指该源正常完成无可用名，不代表无名称或离线 |
| `AddressAccepted(baseSession, historyOutcome)` | 地址阶段终态、冻结引用，安排原初始化资料同步 | 不等待名称，不重写冻结对象；actor不阻塞等待DB |
| `BaselineProfileSyncFinished` | 允许在原锚点启动一次共享源 | 同步失败/已停止/旧token不得启动；启动前再次检查资格 |
| `ServiceObserved / SourceSettled` | 原 mDNS/UPnP 观察与对应阶段状态 | 仅附着已有设备；不回退其他源较新字段 |
| `Stop / NetworkInvalidated / ScopeClosed` | 接纳开关、token、任务终结原因 | 先撤销 token 再清理；控制消息不排在普通观察后等满队列 |

DiscoveryFrame 的 seq 在桥接层按实际回调顺序分配，不改 Core API。
原回调已经串行 publish；完整发现帧可以合并为一个 latest 槽，因为包含当前全体发现。
reducer 接收帧时仅合并发现 owner 的字段并保持进度单调，不替换 evidence store。
旧帧、迟到任务、错误 source/IP、跨网络及重复 terminal 均幂等拒收。

关键次序必须测试：`HostAdmitted → NameObserved → 旧/新 DiscoveryFrame → ServiceObserved`。
名称不消失，scannedHosts 不倒退，同源冲突不被“最后回调赢”抹掉。

### 3.3 可见完成与实际清理分开

| 状态域 | 提议状态 | 含义 |
| --- | --- | --- |
| 地址阶段 | RUNNING / COMPLETED / CANCELLED / NETWORK_CHANGED / ERROR | 只描述原地址发现 |
| 单 IP、单源任务 | PENDING / RUNNING / RESOLVED / NO_DATA / FAILED / TIMED_OUT / DEFERRED / CANCELLED / SKIPPED_POLICY | 已执行与未执行分开；超时不是 NoData |
| 补充阶段 | NOT_STARTED / RUNNING / SETTLED / PARTIAL / STOPPED | SETTLED 是所有允许任务已有逻辑终态，不保证全部取得名称 |
| 资源状态 | logicalSettled、physicalInFlight、cleanupPending | 阻塞系统调用未返回时不得显示物理资源已经归零 |

现有 mDNS/UPnP Enricher 返回Unit，部分启动/收包/描述失败被隔离后只剩“无结果”；
因此外层job返回不能证明每个源正常完成，更不能把未收到结果写成逐设备NO_DATA。
C0的最小接口桥接须暴露真实开始/停止/失败/不完整信息；旧链路未能区分时记
UNKNOWN/原因未确认，不能从Debug日志拼业务结论或伪造成功。该契约适配不改变共享窗口。

现有系统反解可先报可见 TIMED_OUT 再返回成功。C0 将“可见期限到达”与物理任务终态分开：
候选为 `TIMED_OUT + physicalInFlight=true`；只在同 token 仍接纳且总收尾未结束时允许
晚成功替换该源超时状态，否则仅做资源归还。不能因此重复计完成数或开新任务替代。
若维护者选择超时后不再接纳成功，应单列行为差异与覆盖对照。

地址 100% 后可以仍“信息补充中”；补充结束才显示整体已收尾。
取消前已取得的合法 IP/名称保留为**已停止扫描的快照**，不是新一代当前观察。
换网清掉当前观察资格，只展示原有适用 saved profiles，不自动扫描新网络。

### 3.4 Task 147 实施前补充：C0.1 的严格合同

- **完整帧与接纳**：bridge 为 DiscoveryFrame/HostAdmitted 分配同一单调序列。
  仅完整、累计的发现帧可进入 latest 槽；消费时遍历全部 discoveredDevices，
  绝不只处理 `newDevice`。最后的 AddressAccepted 自带完整原发现快照，独立可靠投递，
  即使普通帧被合并也补齐所有已发现 Host。只更新发现自有字段，名称单独归并。
  同序重复/旧帧不倒退进度；不同 Host 的事件不用一个全局“已处理 Host 序号”拒收。
- **所有权**：扫描 owner 分配 generation，Android 网络 adapter 将捕获 Network 的
  存活/策略边界映射成 opaque leaseId 与 policyRevision；C0.1 不实现这些 Android 操作。
  fingerprint 仅作附加一致性条件，不能替代实际 lease。Reducer 由未来单一会话 owner
  串行调用，不从名称或 IP 反推网络。构造时传入既有验证后的有限地址集合，不重写范围校验。
- **两种设备 revision**：`admissionRevision` 是该 Host 首次正向接纳的临时版本，
  名称任务捕获它；`hostRevision` 随发现事实或名称/任务状态变化，用于投影失效。
  普通延迟、角色、进度、其他来源名称的增量不会改变 admissionRevision。
  名称不得拿整个 LanDevice equality 或当前 hostRevision 与启动时值强等，误拒有效名。
  若以后支持明确地址身份替换，须独立失效旧 admission，不能据名称猜换机。
- **启动门**：AddressAccepted 只登记原始地址终态，并发出“原资料同步”描述性 effect；
  同步恢复后必须再次提交带原 token 的完成事件。只有仍接纳、同步成功的状态才发出
  一次共享源启动许可；停止/换网/失败时不发出。effect 不是发包授权：执行 owner 在
  实际执行前必须再验证当前状态；不得让先前缓存的启动 effect 绕过 Stop。
- **完成与资源**：Pending/Queued 未执行，Deferred 未被执行或继续接纳；NoData 只用于
  实际启动且正常确认无数据。TimedOut 是可见期限，不能归还实际 permit；同代仍接纳时
  可接收真实晚成功。NameSettled 携带完整结果作原子终态，不靠丢失的增量恢复冲突。
  重复/矛盾的最终终态不倒退；PhysicalNameFinished 独立确认真实返回，停止后仍可清理。
  SourceSettled 的 UNKNOWN 不等于逐 Host NoData。地址完成与信息逻辑收尾、物理归零分开。
- **可靠事件**：latest 槽类型仅允许 DiscoveryFrame；名称观察/原子终态、源终态、
  AddressAccepted、资料同步完成与物理释放不能走 conflation。Stop/NetworkInvalidated
  由 owner 优先撤销接纳；未来跨线程 mailbox 必须有独立控制通道及任务结果预留槽。
  本轮只实现串行 reducer，不声称已实现可并发使用的 mailbox 或 Android callback bridge。
- **取消真实变化**：未来接入 C0 后，Td 前用户停止时可能已经发起系统名称查询。
  这与旧“完成地址后才补名”的行为不同；停止不等于“本轮从未查询”，已有系统阻塞
  调用可能继续，旧结果不可归并且仍占资源。此次 C0.1 无真实查询，不能用 fixture
  证明系统物理取消或隐私/耗时无变化。
- **UI**：保持最小必要数据、动作和状态；不为每台设备重复添加普通解释。
  本轮完全不接 UI，现有 B1.1 Mapper 的 Completed guard、来源/冲突/截断不放宽。

实际代码位于 `domain/progressive/`，不由现有 VM、引擎或 DI 调用。
ready32、进程实际4、既有1500ms仅作候选契约测试；未设置统一 Td+8s 截止，
也未建立执行器/查询线程。调度器及跨会话预算只预留接口，C0.2 才实施。

## 4. 队列、真实并发与资源预算

### 4.1 非阻塞接纳与公平性

1. reducer 登记合格设备和 `PendingName`；发现回调只提交轻量发现帧并唤醒。
2. ready queue 只放 host/source key；满时仍保留最多 254 地址约束内的 pending 表，
   不丢发现行、不阻塞发现、不为等待 permit 的每个 IP launch 一个 coroutine。
3. 固定 worker 完成后再从 pending 表按首次接纳/FIFO 补队列；保证无重复和饥饿。
4. 明确的收尾/接纳期限到或会话关闭时，仍未接纳的 pending 标 `DEFERRED(reason)`；
   单纯暂时queue满仍等待公平补位，不立即丢掉；Deferred不是 NoData。
   不在页面滚动、点击详情、换语言或搜索时隐式补跑。
5. 确保结果也有边界：每个活跃任务预留一个有界完成槽（含至多允许数的候选）；
   未被 owner 消费前不复用该槽。suspend worker 可等 reducer，Core callback 不等。
   control 使用独立原子失效标记；通知可 conflated，关键结果本身不可被 conflate 丢弃。

### 4.2 预算表

**P = 待评审的起始参数，不是正式默认或已经验证的性能承诺。**

| 资源 | 现有事实 / C0 候选 | 达限语义及计账 |
| --- | --- | --- |
| 主机发现 | 原 32 worker、原 500/250ms、254 地址 | 完全保持，名称不占用其 slot |
| Pending 主机表 | 最多本次合法范围内已发现地址（≤254） | 元数据有界，不为未发现地址登记名称任务 |

| 阻塞反解执行器 | P：应用级 lazy 固定 4 线程，无隐藏无界 work queue | slot 由 runnable 的 finally 在真实返回时归还；cancel Future/逻辑 timeout 不提前归还 |

进程级名称预算的执行器和 ownership 必须独立于单个 VM/session，避免快速停止→重扫
累计旧 `Dispatchers.IO` 阻塞调用。会话关闭不 shutdown 仍接收 framework callback 的
Executor；固定阻塞池也不靠替换/新建线程绕过真实在途限制。应用进程退出由系统回收。

每轮记录 `eligible/admitted/queued/started/resolved/noData/timedOut/deferred/cancelled`，
当前/旧代实际在途、峰值线程/FD、最后新请求与资源归零时间。旧代只做清理统计，
不产生结果/资料写入。现有 NSD 排队、SSDP 收包数量、`getHost().hostName` 隐式系统查询
及 HTTP 物理取消是保留风险，不计入“名称池4即可证明全链路有界”。B1.2/C1 的资源
硬化须单独授权；C0 对照也要测量这些原路径，不能用逻辑计数代替真实资源证据。

“物理4”首先约束自有阻塞调用/线程与socket；DnsResolver的系统daemon内部并发不是App
可完整观测的资源。新系统PTR实验应分别计App未决请求、取消信号和清理未确认项；
无terminal/释放确认不能仅因cancel返回而报物理归零，也不能无界重复发起替代请求。
需预留有界清理隔离额度（P≤4）；额度耗尽暂停该源新接纳并报告Deferred，直到可靠终结，
不凭另一个定时器假装已释放。该API取消后的可靠客户端资源归还方式仍是spike准出项，
不是已证明的系统侧取消合同。

吞吐例：200 个名字都用0.8秒，4并发仅服务时间约40秒。即使发现期间消化了一部分，
短尾窗也未必查完。未批准统一截止时，保留逐源预算并明确无统一物理完成上限；
不可一面承诺固定8秒，一面承诺所有无回应主机都已完整查询。

## 5. 生命周期、发布与已有 B1.1 复用

- **停止/离页**：原子关闭接纳并失效 token，停 pending/新发包，取消可取消 I/O，
  释放自有 socket/锁，幂等停止原 NSD/SSDP；旧 callback 可到达但不归并。
  UI 停止不等待不可中断系统调用；physical cleanup 状态单列。
  尤其原初始化资料同步await恢复后也要重查token，不能只在callback结果到达时拒收，
  却继续为已经停止的会话启动NSD/SSDP。
- **换网/VPN/策略变化**：实际 Network lease 丢失或关键策略变化即中止；相同网段
  也不能沿用旧 token。系统反解没有可选 Network 合同，返回值仍是 best-effort；
  不宣称既有 blocking 调用在换网后绝不访问旧/默认 resolver。
- **重建/进程死亡**：Activity 重建复用现有 VM/会话，不从 Composable 重启；
  真正离开所属工作流按原导航规则停止。进程死亡不恢复网络任务，不制造 Completed。
- **异常**：名称或单一服务失败不撤销已发现 IP、不把设备判离线；源错误保留状态。
- **批量发布**：reducer 的证据先完整归并，再形成不可变 `(token,hostRevision,viewRevision)`
  快照。列表 key 沿用原 scope/IP 或已匹配 profile；不按新名字重排、重置滚动或清输入。
  高优先名称迟到可能原位升级，不能承诺从不跳名；冻结标题/升级次数限制待另行选择。
  reducer/批量物化在可注入的非Main计算调度器执行，mapper只处理变化设备；不在actor里
  阻塞resolver、HTTP或Room调用。源回调先做定长校验/投递，UI仅消费匹配revision的快照。
- **Mapper**：保留一个识别规则实现。当前 Mapper、projector、三个页面只接受 Completed；
  后续 C0 必须设计显式“当前已发现观察”的纯输入资格/适配 API，支持 RUNNING/收尾，
  保持旧 Completed 入口检查。不把正在扫描的 session.copy(status=COMPLETED) 当捷径，
  不在 UI 复制规则。每次数据变更推进 hostRevision，旧 projection 只用于未变化目标，
  保留 Task145 同代更新拒收、取消及增量缓存回归。

## 7. 三项名称来源独立实验（均未实施）

共有前提：仅前台用户扫描已发现、范围内、同捕获网络的 IPv4；不把任何应答转成在线
正证据。实验用隔离 QA 和可注入 transport，只有一个新增源开关；默认全关。
不扩大发现地址/端口，也不改目标防火墙、随机 MAC、远程管理或启用 SMB1。

功能请求仍会暴露必要信息：DNS解析器会收到含目标IP的反向域，且可能转发到上游；
系统Private DNS路径不保证只在LAN内。mDNS问题对同链路成员可见，NBSTAT目标会看到
请求源地址。报告/资料不自动上传；不声称“查询无外部接收者”。实验原始包/名称日志

### 7.1 E-PTR：合规的当前网络 DNS PTR

**目标/事实**：如已发现 `192.168.1.40`，查询 `40.1.168.192.in-addr.arpa` 的 PTR；
只得到解析器给出的反向名称，不是 DHCP 租约表、品牌或硬件型号。
路由器可能从 DHCP 注册名称，也可能完全不发布，不能因没有 PTR 认定设备无名。

分两子实验，不能混为“指定服务器的系统 API”：

| 路径 | 查询与政策 | 输出来源 |
| --- | --- | --- |
| E-PTR-SYSTEM | API29+ `DnsResolver.rawQuery(capturedNetwork, rawBytes,...)`，实现 PTR12 请求及有界 parser；不用当前只支持五类的 DnsRecordType 冒充 PTR | system resolver path，configured DNS≠responding server；缓存来源不明记 Unknown |
| E-PTR-DIRECT | 仅 Private DNS 明确未启用、无 VPN 且策略批准时；对 LinkProperties 中捕获的真实 DNS literal 地址用 Network-bound UDP 查询 | 记录请求目标及校验过的回包5元组、PTR/TTL；仍不认证发送者 |

不猜网关当 DNS，不自动 Google/Cloudflare 兜底。Private DNS active 或状态未知时不发
明文 direct PTR，改用系统路径或 SKIPPED_POLICY；VPN 保持现有不扫描策略，
不得借 WoL 的物理 LAN selector 绕行。DNS 地址可能是 IPv6，只有 scope/interface
可可靠使用时尝试；不可靠则跳过该 server，并如实报告。

P 预算：全局名称池≤4；每主机/获准服务器至多1次、服务器至多2个、无重试。
direct 每次800ms绝对等待，两个顺序目标则总主机预算至多1600ms（另加本地解析预算），
不能把“每次800ms”写成“两个服务器总共800ms”。报文≤4096B、RR≤64、压缩跳转≤16、
包内 CNAME 链≤4；本实验不自动追查新名字、不新增 TCP fallback，TC 截断明确失败/不完整。
取消关闭自有 socket；系统 API 用 CancellationSignal，迟到回调由 token 拒收，
callback Executor 长期可接任务；系统内部重传/执行不能由逻辑取消计数证明已结束。

校验 QR/ID/question/class/type、长度、RCODE、owner/包内别名链、回包地址/端口及当前网络。
拒绝指针环/越界、伪造不相关 Answer、非法 Unicode/控制字符、超长名称；TTL 按无符号读取。
同 `(source,server,owner,name)` 去重、TTL取保守值；不同服务器相异名并列，不最后回包赢。
NOERROR 空记录/NXDOMAIN 为该反查源 NoData，SERVFAIL/REFUSED 为失败，timeout 单列。

**适用与验收**：电脑、手机、平板均以实际 DNS 登记为条件；不要求系统默认为其发布名称。
同网预置有 PTR、无 PTR、陈旧/冲突 PTR 的受控 DNS，对照已知真实终端；
证明只发送到获准路径，Private DNS/VPN 下无明文绕行，有增益再讨论默认。
API与政策依据：[DnsResolver](https://developer.android.com/reference/android/net/DnsResolver)、
[LinkProperties](https://developer.android.com/reference/android/net/LinkProperties)。

### 7.2 E-MDNS-R：已发现 IP 的 mDNS 反向 PTR

**目标/事实**：对该 IP 的反向 owner 询问 PTR，取得 responder 声明的主机名；
这不是浏览 `_http/_ipp/_smb` 实例目录，也不是新增 ESPHome 默认服务。
RFC6762 对 link-local 反向域有明确规定，不能推为所有 RFC1918 设备必须应答。

推荐先验证 RFC6762 §5.1 的 legacy one-shot 模式：一个会话共享、绑定捕获网络/接口的
临时端口 UDP transport，向 IPv4 `224.0.0.251:5353` 发单问题查询并接收其单播回复，
按 transaction ID、reverse owner、question 与接口归属关联。发送的组播IP TTL设为255；
legacy应答应保留问题/ID、不带cache-flush，RR TTL按该模式保守使用（不超过10秒），
不能拿它冒充对端原记录完整生存期。避免抢占 NSD 的5353监听端口。
不默默切到另一种5353组播监听模式；如 legacy 模式收益不足，完整 querier 需另行方案。

P 预算：≤4 outstanding、发起速率≤5次/秒、每 IP 1次、无重试；800ms快速档与3000ms
较长档**分别运行**。单包≤9000B、RR≤64、名字/压缩校验复用前项边界；处理超长/截断
与包数量上限（P：每会话256个接纳响应或128KiB解析 payload），达到上限记不完整。
一个有界接收循环分发到预留任务槽，不为每个包/主机创建线程。

只接受符合所选查询模式的 ID/owner/class/type、源端口和链路检查；允许同链路 sleep proxy
代表目标回答，但明确是代答观察，不能把 packet source IP 当目标硬件的认证。
重复/相异 PTR 有界保留；TTL=0 按撤回处理，不沿用已撤回值；只有正 TTL 也不证明“本次全新”。
不自动根据返回 hostname 再发 A/AAAA/HTTP，不跟随 URL、TXT 或其他服务。

raw transport 自己拥有 socket/接口选择，取消和换网关闭它。legacy 单播接收不必为此
加入5353组播组；若实现改为接收组播，须先明确 MulticastLock 的独立 owner、幂等释放
与 NSD 共存验证，不能释放 NSD 的锁或关闭其长期 Executor。现有 NSD 保持原窗口。
Private DNS 不把这一路变成加密系统 DNS；局域网其他成员能看见组播问题。
VPN、客户端隔离、raw LAN 访问被系统阻止时跳过/失败，不绕行，不误写“目标无名称”。

**适用与验收**：macOS、Avahi/Linux、部分 iOS/iPadOS 或应用 responder 可能有收益；
Android 支持 NSD 不等于系统默认广播设置中的设备名。每类实物分别对照目录浏览与反查，
含锁屏/idle/代答/多播阻断及 spoofed owner。比较两档窗口的实得名与额外耗时，
无稳定新增有效名则不默认启用。协议依据：[RFC6762 §§4、5.1、6.7](https://www.rfc-editor.org/rfc/rfc6762.html)。

### 7.3 E-NBSTAT：Windows 条件性节点状态查询

**目标/事实**：已知发现 IP，向其单播 UDP137 发 wildcard `*` 的 NBSTAT（0x21）
Node Status 请求，读取名称表。不是先知道电脑名的 NBNS 正向查询，也不是广播扫描。
对端 NetBIOS over TCP/IP 和对应防火墙策略须允许；Samba 也可能回答，不据此认证 Windows。

P 预算：全局名称池内2–4活跃、每 IP 1次、500ms绝对期限、无重试；回包≤4096B、
名字表≤32项、每项验证15字节名称+suffix/flags与报文剩余长度。
仅将合法 active、非 group 的工作站名（suffix 0x00）作为优先候选；组名、服务后缀与
统计字段分开，不把“WORKGROUP”当电脑名。非 ASCII/编码不明者记不支持或保留技术证据，
不使用替换字符拼成平台结论。返回 UNIT_ID/MAC 不导入匹配器、OUI、Profile 或 WoL。

校验 peer IP/port、ID、opcode/QR/RCODE、RR type/class、RDLENGTH/数量/压缩边界。
重复名去重，多名有界保留；不按最后一包定主名，不抓 banner/认证，不自动连接 SMB。
自有 socket 绑定捕获网络，取消关闭，VPN/网络变化/权限限制时不换路径重试；
Private DNS 不参与 NetBIOS 名称服务，但不因此绕开当前 App 的网络政策。

未知 IP 可能是 Windows，不能仅“已识别 Windows”才查询而循环依赖；也不能用没有445
排除 UDP137。受控实验可限定“已有发现但无有效自动名”的 IP，必须报告因此遗漏的组，
最大请求量为合格未知设备数（≤254），不只统计应答者。无回应不等于非 Windows。

**验收**：Windows台式/笔记本原安全设置下分别测试，开/关NetBT条件分组，
至少一个 Samba 反例及手机/平板无回应组。验证 group/suffix过滤、假包与取消，
不要求关闭防火墙/启用SMB1。收益不足则保留按需/延期候选。
依据：[RFC1002 §§4.2.17–18](https://www.rfc-editor.org/rfc/rfc1002.html)、
[Microsoft nbtstat](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/nbtstat)。

1. **冻结发现，不冻结完整识别**：继续由原 UseCase 对引擎 COMPLETED 的原始发现会话

   在该门之后由副作用队列执行，不把等名称/额外DB写塞到共享窗口启动门，也避免原
   空名称快照后到覆盖已经保存的新名。需分别比较原初始化写与新观察补充写的时序。
5. **发现拥有时间**：Last Seen 用 discovery device.lastSeen；First Seen 不因补名改变。
   repository 的 updatedAt 可按既有更新行为变化，不能因此说观察时间刷新。

7. **新协议实验隔离**：先只在QA观察/计分，不偷偷落库旧无来源的hostname字段。
