## Review conclusion

No blocking network-isolation, protocol-association, identity-write or resource
lifecycle defect was found within the reviewed implementation and available
fixtures/live evidence. One evidence-presentation defect was fixed: when current
NBSTAT supplies a hostname and a saved profile also has an older hostname, the
current value must not carry the saved-field marker. The change only corrects
`DeviceCenterPresentation.savedIdentityFields`; the saved value is untouched.
A fixture verifies current name, NBSTAT source, absence of the saved marker and
preservation of the old saved value.

## Reviewed integration

- NBSTAT and SSH parsers are single shared feature implementations, byte/line
  equivalent to their previously reviewed source except the NBSTAT KDoc. Existing
  QA callers resolve these classes; the production adapter invokes the same parser
  rules. No copied alternate parser. NBSTAT validates target source/port, transaction,
  wildcard owner/question association, TTL=0 and bounds/conflicts. UNIT_ID is ignored.
- The production DI singleton supplies AndroidLanHostEnricher; synthetic Hilt tests
  deliberately replace it with NoOp. The explicit opt-in real-LAN audit instead
  constructs the production adapter. Normal Debug DEX contains the adapter and both
  parsers, and has no private authorization/target assets.
- Only published discovered remote hosts are offered. NBSTAT rechecks missing
  automatic name at send time. Once-per-session admission prevents retries and
  duplicates. SSH is one TCP22 identification connection, never login/commands or
  a preliminary extra port check. A closed discovery socket is not a reusable stream.
- The shared Task171 mapper keeps names, category and service independent. NBSTAT
  supports Possible Computer; SSH alone remains Unknown category. Explicit UPnP
  IGD evidence and conflicts use the original rules; neither inventory truth nor
  service versions create hardware/OS/model claims. Manual name/type remains first.
- Existing brand/model and source evidence is retained. New facts remain transient;
  no Room schema, identity key/matcher, History serializer/freeze point, First/Last
  Seen or saved user-field changes. New source callbacks bypass profile observation
  sync; original discovery/C0 observation updates keep their existing ownership.

## Resource, permission and cancellation boundaries

New protocol budget remains two process-wide physical workers with executor queue
32, plus two session workers and channel 32. Admission is capped at 254; a full
channel skips that host for this round. No unbounded waitlist or retry. NBSTAT wait
500 ms; SSH connect 250 ms/read deadline 600 ms; two-second post-discovery cutoff.
Discovery does not await new identification. Existing C0 4/32/254/1500 ms/15 s,
core discovery concurrency/timeouts/ports and shared multicast timings are unchanged.

Sockets bind to the captured default Android Network. Lease revalidation before I/O
checks the captured network identity and routing policy; generation/fingerprint and
current-session guards reject obsolete delivery. Stop/rescan/network loss cancel
jobs, close resources and remove queued work. Busy workers are not replaced; the
fixed process executor's idle threads intentionally persist. Timeout, protocol,
permission/bind and executor-rejection failures return no evidence and release
resources; a failed source cannot become online evidence.

Both app and core/network source manifests already declare ACCESS_NETWORK_STATE.
The merged normal Debug and Release manifests contain it; no permission was added.
The SuppressLint is limited to the library's guarded active-network accessor, whose
SecurityException path returns null and fails closed. The consumer manifest evidence
was checked rather than relying on the suppression. Network/lease files are unchanged.
