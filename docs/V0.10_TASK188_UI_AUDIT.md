## 实现与边界

- 当前连接/附近 AP 使用协调的紧凑卡片：SSID、BSSID、RSSI/dBm、频段、信道。
  真正匹配当前连接的 AP 仍有标记。RSSI 不再显示优秀/良好/一般等评价，
  无障碍朗读也仅说明实际信号数值，不朗读主观等级。内部信号分级模型未改。
- 移除卡片“说明与限制”、常驻教学段落和重复来源。观测时间、来源、
  安全类型、扫描宽度、频率/中心频率、Wi-Fi 标准在展开区保留。
  默认当前连接没有“连接采样时间未提供”的占位段落。
- 顶部准确保留缓存、权限、Wi-Fi 关闭、失败、保留结果、过期等既有状态。
  搜索、频段筛选、刷新和信道视图不变。大字体频段栏沿用可横向滚动布局。
  当前连接与扫描 AP 的 RSSI/宽度/来源仍各自独立；不借扫描宽度填当前连接。
- Device Detail 顺序为概要 → 本地资料/编辑 → 网络检测 → WoL → 基本信息
  → 观察状态 → 识别依据。只移除独立“网络关系”卡片，底层 scope、会话、
  身份匹配不改。保留 Ping/端口检测/端口扫描、收藏、编辑、冲突及可展开证据。
- WoL 空白/纯空格 MAC 保存为 `null` 配置，忽略此时无意义的端口输入；
  非空 MAC/端口仍严格校验。数据库同次更新清空 `wol_mac_address` 和
  `wol_udp_port`，不是存储空字符串。清除 WoL 不再删除只有 WoL 的资料行。
  保留观察 MAC、身份、名称/类型/备注/收藏及 First/Last Seen（仅配置修改时间更新）。
- 清空后无发送按钮，ViewModel 也拒绝调用发送器；发送前在同一 WoL mutex
  内读取持久化配置，避免延迟 UI 状态继续引用旧 MAC。再次打开配置默认端口为 9。
  原有同网段配置/发送约束不变，没有额外重置按钮或确认弹窗。
- Room schema、实体/DAO、扫描/识别/网络算法、超时并发、权限、依赖、版本、
  签名、Play 设置均未改。PRODUCT_PLAN/DECISIONS 已记录维护者确认的新展示原则
  和清除行为；旧 Wi-Fi 设计加了明确的当前原则覆盖说明，历史研究仍保留。

### WoL 持久化证据

专项显式启用 `task188Room=true` 才使用 QA 包中的独立 `task188-wol.db`；
其它 instrumentation 的原有 fake repository 保持原行为。未打开正式 App 数据库。

1. 通过真实界面保存有效 MAC 与 UDP 7，读取实际 Room 记录验证。
2. 清空 MAC 保存，通过 Room 与独立 SQLite 只读查询同时确认 MAC、端口为 NULL。
3. 比较清除前后整条资料（仅允许 WoL 和配置更新时间变化）；观察 MAC 与用户资料不变。
4. 真实返回操作、再次进入、ActivityScenario.recreate 后保持未配置；
   直接调用发送入口也没有调用 fake sender，更未发送 UDP 包。
5. 再次配置后，用纯空格 MAC + 无效端口保存，仍正确清除整条配置。
6. 两次独立 instrumentation 中间 `am force-stop` QA 包；记录不同进程 PID，
   第二进程从同一磁盘数据库恢复相同 ID、空配置和原资料；最终两阶段 PID 为 15467 / 15668。
7. 执行一次 **Fake Engine 重扫**（无家庭 LAN 探测），已清除配置未恢复；
   ID、观察 MAC、身份、手工资料、First Seen 不变。Last Seen 按既有扫描观察规则更新，
   不将其误报为清空操作修改 Last Seen。
8. 无效非空 MAC 按钮禁用；重新设置新有效 MAC 使用默认 UDP 9。

原始证据：`build/task188/final-wol-A.log`、`final-wol-B.log`，以及
`screenshots/task188/wol-*.txt`（合成资料、进程 PID、scanStarts/wakeSends）。
最终设备已安装包的 SHA-256 与下方归档 QA APK 一致（`device-check.json`）。
此前调试中修复了测试 Edit 多匹配、Compose StateFlow 读取 lint 问题及旧导航
测试写死中文标签的问题。最终成功结果以 `final-*` 与 `navigation-profile-verified.log`
为准；旧失败日志保留，不隐藏为首次即通过。
