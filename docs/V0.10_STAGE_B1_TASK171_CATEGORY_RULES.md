## Existing architecture and category audit

`LanRecognitionMapper` admits the current network/session/target and maps existing
PTR/mDNS/UPnP observations to typed, bounded hints. Its service, platform/board,
model and name-clue rows are not a general hardware classifier. Its ESPHome
platform self-report/name clue remains a platform observation, not automatic IoT
hardware or server classification. This production mapper is unchanged.

`DeviceType` is the existing profile vocabulary (Computer, Server, Router, NAS,
Printer, Phone/Tablet, TV/Media, Smart Home, Network Device, Other). Profile UI
prefers `userDeviceType` over stored `detectedDeviceType`; the examined LAN paths
do not populate these from the experimental QA classifier. Camera is only an
additional QA vocabulary entry, not a Room enum/schema or product feature change.

The QA retains `QaCategoryMapper` over checked C0 output plus validated per-target
experimental observations. It has no sockets, resolver, repository or inventory.
Name projection, category assessment and SSH service projection remain distinct.
Levels are now exactly CONFIRMED / POSSIBLE / UNKNOWN. The former SUSPECTED value
in archived JSON remains a historical label; captures are not rewritten.

## Merge, conflict and lifecycle contract

- Consistent NBSTAT Possible and WSD Confirmed Computer combine into Confirmed
  while retaining both reasons. Many copies of NBSTAT stay Possible.
- Incompatible explicit categories, or incompatible weak/strong category claims,
  return Unknown with all reasons. No arrival order or duplicate count wins.
- A name conflict suppresses the automatic name and NBSTAT candidate, but does
  not refute independent WSD category evidence. The name conflict remains in
  details. This fixes the earlier coupling of name conflict to all categories.
- Failed/invalid metadata cannot supply metadata-level proofs. A previously
  validated Probe Computer claim can survive a metadata timeout/rejection;
  invalid/generic/association-conflict/no-response states cannot supply proof.
- Current C0 status and the existing owner/gate/Network Lease reject old work.
  QA owner continues per-target filtering before classification, and clears on
  Stop, Rescan and network invalidation. No category work occupies host workers.
- User name/type priority is presentation-only and does not mutate the automatic
  evidence, counted success, saved profile or persistent identity. No Notes,
  Favorite, WoL, History freeze, First Seen or Last Seen path is changed.

Default QA category rows are Computer / Possible computer / Unknown type (and
Chinese equivalents). Confirmed does not add another stacked level badge;
details retain self-report/non-authentication and source qualifiers. Software
versions stay in details. No scores or explanatory cards were added.
