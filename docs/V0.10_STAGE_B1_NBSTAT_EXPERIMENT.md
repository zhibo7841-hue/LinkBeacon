## Protocol and parser review

Test-only source: `app/src/nbstatTest/java/com/networktoolbox/nbstat/` is compiled
only into JVM and instrumentation tests; it is not a main source set or Hilt binding.

- Original implementation of wildcard `*`, first-level encoded NetBIOS name,
  unicast UDP137 NBSTAT `0x21` / IN request with randomized 16-bit transaction ID.
- Validate peer IP/port, transaction, QR/opcode/AA/TC/reserved bits, RCODE, counts,
  question if present, RR type/class, exact RDLENGTH and bounded name encoding.
  Compression requires backward in-packet pointers, bounded traversal and no cycles.
- Maximum response 4096 bytes, maximum 32 name entries, exact 18-byte entries and
  46-byte statistics trailer. Oversized/truncated/trailing or malformed data is rejected.
- Parse suffix and flags separately. Only printable, conservative ASCII names with
  active, non-group suffix `0x00`, without conflict/deregister flags, are candidates.
  Group/workgroup and service suffixes remain observations, never workstation names.
  Unsupported text becomes unusable, not replacement characters or an OS claim.
- Exact entries deduplicate; different workstation names or inconsistent flags for
  the same entry return CONFLICT without selecting a winner. No usable name,
  malformed response, remote error, policy block, transport failure and receive
  timeout are distinct outcomes. `TIMEOUT_NO_RESPONSE` means none observed in-window.
- UNIT_ID/statistics bytes are checked for bounds then ignored; no MAC field is
  exposed to matching, OUI, WoL, Profile, online detection or persistence.
- Strict experiment subset: empty NetBIOS scope, one answer, bounded ASCII names;
  unusual/custom-scope or non-ASCII deployments are not certified by these fixtures.

Protocol references: [RFC1002 §§4.2.17–18](https://www.rfc-editor.org/rfc/rfc1002.html),
[Microsoft suffix conventions](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nbte/6dbf0972-bb15-4f29-afeb-baaae98416ed),
[Android Network socket binding](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.DatagramSocket)).
These support packet/API semantics, not a claim that all Windows devices respond.
NBSTAT is unauthenticated: correct address/port/ID checks do not defeat an on-LAN
spoofing adversary. A compatible responder (including Samba) does not prove OS,
brand, model, physical identity or exclusive ownership of a name.

## Decision recommendation, not product approval

The experiment shows a real single-target increment, but two silent targets and one
responsive Windows sample are insufficient for a default-on fallback. Keep isolated/
on-demand research; do not enable NBSTAT in production. Any production proposal needs
broader evidence, explicit source wording and resource/privacy/safety review first.
Do not use this finding to enable SMB1 or alter target security policy.

Next candidate is a **separately authorized** captured-network DNS PTR experiment:
reuse strict target allowlisting, respect Private DNS/VPN policy, distinguish system
resolver/cache from direct DNS evidence, and compare against this retained baseline.
No DNS PTR, reverse mDNS, ESPHome expansion or other protocol starts in Task162.

## Task164 — isolated parser validation repair (2026-10-25)

Scope is limited to the test-only protocol parser and JVM regressions. No production
discovery integration, device installation, target login or new UDP137 request.

- Request construction and response validation share the same 16-byte wildcard
  query name. The bounded name reader follows existing compression pointers and
  decodes the A–P label before comparing all 16 bytes (including suffix). It does
  not compare raw fixed offsets. The existing one-label/empty-scope restriction,
  backward-pointer/bounds/cycle checks remain in force.
- Both RR_NAME and an optional QDCOUNT=1 echoed question must match that query.
  QDCOUNT=0 responses and a compressed owner pointing to the correct echoed
  question remain accepted. No generic query-name API is needed: this experiment
  only constructs the wildcard/empty-scope request.
- The node-status response TTL must be zero across all four bytes. Nonzero TTL
  returns INVALID_RESPONSE before any name-table candidate is produced.
- Exact source IP/port, transaction ID, header, packet/table lengths, group/active/
  conflict filtering and external lease/session validation are unchanged.

### Test-first evidence and offline compatibility

Twelve new JVM regressions were added before changing the parser. The pre-fix run
had 46 tests, with seven expected failures: different valid owner, owner suffix,
wrong question, wrong question plus compressed owner, wrong owner after correct
question, nonzero TTL after compressed owner, and nonzero TTL bytes. Existing
34 tests were retained without removing assertions. After repair, all 46 pass
(40 protocol + 6 authorization/transport boundary tests).

New coverage also explicitly preserves the correct empty-scope/QD0 owner, correct
QD1 uncompressed owner and zero TTL, and rejects nonempty owner/question scopes.
Existing tests retain valid compressed owner, illegal pointers/cycles, truncation,
wrong transaction/source, conflicts and group filtering.

All four saved Task162 T09 responses (API12/API16, 500/1000ms) replay successfully
through the repaired parser, with the same candidate across all four. All twelve
saved requests still match the query builder. For each saved response, an in-memory
wrong-owner variant and nonzero-TTL variant are rejected. Original evidence bytes
are unchanged. Offline peer parameters are synthetic documentation addresses;
this does not reverify the original network source or constitute a new device test.
Helper/logs stay in ignored `build/task164/`; private packets/names are not fixtures
in Git. No new real-device compatibility testing was performed.

### Remaining boundaries and next-step recommendation

OEM/non-ASCII decoding, general nonempty scopes, retries and absolute total query
deadline remain out of scope. The receive windows remain 500/1000ms; a separate
deadline follow-up is still needed if total query budgeting is later required.

This repair cannot change Task162's eight sent=1/received=0 observations. T05/T06
did not reach the parser; their naming issue is not resolved or diagnosed here.
Next, separately authorized target-local read-only inspection should establish
Windows NetBIOS/interface/UDP137 listener/effective firewall state, and Ubuntu
nmbd (or equivalent NBNS responder)/listener/interface/firewall state. Do not enable
services, SMB1 or alter firewall policy to obtain a positive result. T03 DNS PTR
remains a separate proposal, not an automatically started experiment.

### Review result

No blocking protocol, authorization or privacy defect was found within the stated
isolated experiment scope. No source/test correction was needed in Task165.

- Rechecked RFC1002 sections 4.2.17/18: wildcard request, network byte order,
  NBSTAT/IN, response flags/counts, requesting RR_NAME, zero TTL and bounded
  name-table/statistics layout. Task164 compares decoded names, not fixed offsets;
  correct QD0/QD1 and compressed owner remain valid. Source/transaction rejection,
  malformed input, group/conflict/active/suffix filtering remain covered.
- All 46 test methods and their assertions remain intact (34 original, 12 added).
  The retained Task164 red log confirms seven pre-fix failures. Task165's fresh
  specialist run passes 40 protocol and 6 boundary tests. Four saved real responses
  replay as NAME with the same candidate; four wrong-owner and four nonzero-TTL
  derivatives reject. Twelve saved requests still match the request builder.
- The real-query entry requires both explicit opt-ins, QA package, pinned local
  prefix and exact target IDs/IP mapping. Numeric address construction avoids DNS;
  direct-route and captured-Network validation prevent alternate-network selection.
  Network lease invalidation closes the active socket. VPN is blocked, attempts
  are sequential and persistently marked, with no retries or broadcast scan.
- Cancellation/finally close and worker/lease cleanup were inspected and simulated
  boundary tests rerun. This does not add real handover or device compatibility
  coverage. Tiny concurrent network changes and unauthenticated UDP do not become
  authenticated identity guarantees; nothing writes these observations to Profile.
- The experiment is test-source-only. Main source search has no NBSTAT integration;
  the ordinary Debug APK contains no experimental package/class descriptors or
  private authorization assets and retains its previously recorded SHA-256.
- Existing evidence remains 12 sends, 4 receives from one T09 target, 8 receive
  timeouts from T05/T06. The receive count increments before parsing. Neither the
  fix nor this review establishes why those targets were silent or improves the
  current production C0 identification rate.
