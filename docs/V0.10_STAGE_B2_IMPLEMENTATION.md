## Files and contract

New production files, both in `feature:wifi/presentation`:

- `WifiExplanation.kt`: closed Wi-Fi codes, typed arguments, scopes, evidence,
  placement and explicit input/time types.
- `WifiExplanationMapper.kt`: stateless pure Kotlin projection; not called by
  any existing ViewModel, screen, Engine, repository or app entry point.

New tests: `WifiExplanationMapperTest.kt`, `WifiExplanationIsolationTest.kt`.
This review note is the fifth new file; no existing source or resource changed.

```text
WifiExplanationMapper.map(snapshot: WifiAnalyzerSnapshot,
                          context: WifiExplanationContext): List<WifiExplanation>
```

- Context requires `ready`; selected band and the existing permission disposition
  are presentation facts. Optional `nowElapsedMs` is an explicit monotonic time
  input, not an implicit clock, timer, locale or request service.
- Output includes code, typed arguments, field, evidence source and scope:
  scan, connection Network identity, scanned AP BSSID/frequency or unknown-row
  index, selected band, or band/channel. Opaque network IDs/observation identities
  are internal correlation data, not new user-facing strings or persistent keys.
- `STATUS` must remain directly visible; `FIELD_QUALIFIER` accompanies its field;
  `EXPANDABLE` is optional educational explanation. The mapper applies no
  two-message cap and assembles no English/Chinese sentences.
- Valid dBm is checked with the existing `WifiSignalClassifier.validRssi`;
  the supplied Core grade is preserved, not recalculated using another table.
  Unknown grade does not erase an otherwise valid dBm reading.
- Raw timestamps and batch freshness are retained. Age is calculated only with
  an explicit nonnegative monotonic reference. Missing/nonpositive/future stamps
  have no invented age; without a reference, positive normalized timestamps can
  be passed through but no age/future-time verification is claimed.
- A retained batch can coexist with a request, failure or restriction. A new
  pending request does not inherit the previous batch's request-failure message,
  nor relabel its raw freshness. Batch freshness is not a per-AP freshness claim.
- Access conditions retained only in a batch are historical evidence, not proof
  of the current Wi-Fi toggle, location service or permission state. Without
  corroborating current access/state evidence, they use
  `RETAINED_SCAN_ACCESS_CONDITION` with a typed issue. Explicit current Wi-Fi-off
  evidence still suppresses old connection data; retained APs remain qualified.
- Repeated evidence merges only when code, scope, field, placement and typed
  arguments are equal. Different typed facts are preserved rather than taking
  the first fact and combining unrelated sources. Equivalent state/batch/access
  evidence retains all distinct source references. Missing fields, connections
  and AP scopes are not collapsed. Unknown BSSID rows stay independent; no
  SSID-based identity.
- Permission disposition carries `PRESENTATION_CONTEXT / PERMISSION` evidence
  as well as the supplied access source. Signal facts identify both RSSI and
  the supplied signal-level field; the mapper does not infer permission or grade.
  Inputs are the existing normalized snapshots/unique channel summaries, not
  arbitrary raw Android scan rows. Existing observation sorting is untouched.

## E01–E13 implementation mapping

| Rule | Mapping / boundary |
| --- | --- |
| E01 | `FINE_LOCATION_REQUIRED` with the existing permission disposition; no permission action is executed |
| E02 | `LOCATION_SERVICES_DISABLED` only from current access/state evidence; batch-only conditions remain historical |
| E03 | Current `WIFI_DISABLED` suppresses old connection signal while retaining qualified AP results; a batch-only old condition cannot hide a current connection |
| E04 | `SCAN_REQUEST_REJECTED`, request/waiting/no-fresh/error codes independent of cached data |
| E05 | `SCAN_ACCESS_UNAVAILABLE`; no confirmed throttling, hardware failure or retry countdown |
| E06 | Updated/cached/unknown/retained batch codes, raw times and optional explicit ages; never permanent "just now" |
| E07 | Connection-scoped signal observation and expandable receive-signal limits/weak-signal explanation |
| E08 | The same explanation template with AP scope, its own observation time and batch provenance; no connection backfill |
| E09 | Reuse supplied `WifiChannelObservationSummary` values; band/channel/AP count and limits, no recount or ranking |
| E10 | Selected band not observed vs absent from limited available results; no hardware-support inference |
| E11 | Intentionally excluded: existing search/presentation owns search-empty states; no search input or Core-count change |
| E12 | Field-specific unavailable facts, unknown identities/time/grade/width; no zero substitution or hidden-SSID/MAC assertion |
| E13 | Field qualifier `LINK_SPEED_NOT_THROUGHPUT` only for the supplied positive link speed |

Connection Channel Width is explicitly not collected; actual AP width, including
80+80 MHz, is retained separately. No fabricated quality score, interference,
congestion threshold, best channel, distance, throughput, latency or packet loss.

## Task 137 review findings

The review covered both implementation files, both test files and this note,
against the existing Core snapshots and Stage B contract. These are mapping
boundary findings from deterministic fixtures, not claims of new platform faults.

| Finding | Fix and regression evidence |
| --- | --- |
| A retained batch access issue could become a current global condition and suppress a valid connection | Distinguish uncorroborated retained conditions from current access/state. Test all four access issues, plus corroborated Wi-Fi-off evidence merging and connection suppression |
| Deduplication could discard differing typed access facts sharing code/scope/field | Include placement and typed arguments in the semantic key; merge only equivalent facts and their evidence. Test differing change-Wi-Fi permission/platform restrictions and existing equivalent repeated issues |
| Permission disposition lacked its actual presentation-context provenance | Add explicit context/permission evidence alongside the access source; test permanently-denied disposition provenance. Signal grade provenance is also explicit |

The first three regression fixtures failed before the fixes and pass afterward
(`build/task137/review-before-fix.log` records the reproductions). No unresolved
B2.1 blocker was found. The review also confirmed:

- Inputs are existing normalized Wi-Fi facts plus explicit read-only presentation
  context. Output uses closed codes and typed facts, not finished UI sentences.
- Source/scope identity and the three placement classes stay separate; cached
  results, current restrictions and request failures can coexist without being
  converted into a single quality or fault score.
- Existing RSSI validation, supplied grades and Unknown semantics are preserved.
  Connection and AP readings are never backfilled or combined, even with the
  same SSID/BSSID. Existing scan ordering and channel counts are unchanged.
- No hidden clock, service, network/permission/storage operation, input mutation,
  new dependency or generic rule framework was introduced. The two existing
  isolation tests were rerun, alongside source-level dependency/call-site review.
- For A AP rows, C channel summaries and E emitted facts, traversal is O(A+C),
  hash-key deduplication is expected O(E), and stable placement ordering is
  O(E log E), with O(E) intermediate/output storage. There is no pairwise AP
  comparison, scan recount or per-row I/O. A 500/1,000-AP fixture checks separate
  identities and proportional per-row output; it is not a timing benchmark,
  RF measurement or device performance certification.
