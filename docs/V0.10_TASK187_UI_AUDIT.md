## Implementation

### Wi-Fi AP cards

- One full-width list, smaller card padding (12 dp horizontal / 8 dp vertical) and 2 dp internal gaps. No crowded two-column AP grid.
- Default SSID, complete BSSID, actual RSSI/existing signal label, band/channel, matched-current-connection status and per-AP observation age remain. Scan-cache/permission/availability restrictions stay at their existing levels.
- Full security, source, observed width/frequency/centers/standard/DFS and technical explanation move under the existing per-AP disclosure. Expansion is not automatic.
- Search, band/channel controls, refresh, thresholds, source semantics and scan/network execution remain unchanged. Signal accessibility descriptions remain intact.
- During screenshot review, an intermediate incorrect separator character was corrected to the original middle dot. Final screenshots are captured again from the final QA APK.

### Shared LAN rows

`LanDeviceCard` serves both LAN Scanner and Device Center. Two **logical** information lines: name plus existing qualified category/status; IP plus at most two distinct observed service types (and necessary saved/not-observed status). Names retain ellipsis, while category and service text may wrap at large font rather than shrinking.

User-defined type/name, local/gateway role, favorite and quick-wake actions retain priority. Confirmed/Possible mapping reuses `LanRecognitionPresentation.category`; absence of a mapped category displays localized “Unknown type” / “类别未知”. Service observations are not promoted to category evidence. Default long source/version/latency/MAC paragraphs are removed from the list; full evidence remains in detail. Conflict and truncation/limitation messages deliberately remain visible even if this exceeds two physical text lines. No discovery, ordering, online, identity, favorite or wake algorithm changes.

### Device Detail

Order: overview (name/IP/qualified category, favorite/edit) → local profile → Ping/Port Check/Port Scan shortcuts → basic information → relationship → observation → recognition → Wake-on-LAN.

Main recognition category, uncertainty, conflicts and incomplete-evidence notices stay visible. Full reported/service/weak-clue evidence, provenance/times and PTR/mDNS/UPnP names use the existing saved expansion state; no evidence is removed. When only original names exist without a recognition panel, a disclosure still makes them available. Profile editing, favorite, tool routes, and WoL are not collapsed.

### Task 186 follow-ups

- Home chooses 1/2/4 metric columns from **actual available width and font scale**; at phone width and 1.5×, IPv4 and netmask no longer compete in one row.
- Registration fields stack label/value when the effective width is below 280 dp; wide layouts retain a two-column row.
- Chinese tool subtitle is `域名与IP注册`.
- Result disclosures share a 2 dp gap while keeping standard button touch size.
- Localized date rows omit the repeated timezone suffix; one result-level timezone note remains, and original timestamp values remain in expanded fields/raw response and copy. Date-only or unzoned registry values retain the existing conversion boundaries. No parser, result-model or protocol changes.
