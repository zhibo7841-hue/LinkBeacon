**主要结论：**

1. 新增注册查询确实把用户选择的注册域名或公网 IP 发给外部注册服务。IANA 目录请求、RDAP HTTPS 查询、WHOIS 明文 TCP 43 查询是不同的数据流；不是上传家庭 LAN 清单，也不是零设备外传输。
2. 未在本次检查的生产调用链发现自动向 LanYun Studio 后端上传 History、设备资料、整份报告或原始注册响应的实现；没有新增广告、分析或远程崩溃上报 SDK 的直接依赖证据。该结论不等于所有系统、接收应用和注册服务均不保留数据。
3. 当前双语政策已说明大部分原有探测、外部解析器、代理、分享、日志和删除边界，但未明确覆盖 RDAP/WHOIS/IANA、新增 NBSTAT/SSH、TXT/Markdown 及新导出策略。清除 WoL 后保留资料身份的行为也需澄清。
4. Website/TLS 导出采用保守白名单脱敏；自动网络诊断完整报告仍保留技术数据。两者不能统一宣传为“全部匿名”，也不能把保存到 SAF 提供器一概称为仅保存本机。
5. 仓库 Data Safety 文件仍是 v0.9.x 的 **Draft / Pending Maintainer Review**。未取得当前 Console 已提交答案或其批准记录，故本轮不能宣布“无需调整 Data Safety”或替维护者填写最终 Yes/No。
6. [Stage D 的 DISCLOSURE-010](V0.10_STAGE_D_PRE_RC_AUDIT.md) 尚不能据本审查自动关闭。RC 前应完成本文件第 10 节的披露内容及申报依据审查；本轮不部署政策、不改 Console。没有据此要求改变功能、扩大产品范围或重做检测算法。

方法：检查源文件关键执行段、调用/持久化/导出边界、Manifest、依赖配置和政策文本；对 342 个 `app/core/feature` 下 `src/main` Kotlin 文件作后台调度、标识符、SDK 和日志入口检索。命中再沿实际注入和调用链核对；测试夹具、QA 实验代码、静态目录内容不当作普通 Release 行为。缺少抓包、服务端留存和 Console 证据的结论明确留空。

没有执行公网 RDAP/WHOIS、LAN 扫描、Traceroute、WoL、App 安装、真机数据读取、全量测试或构建。联网仅用于阅读 Google 官方定义；不向注册服务发送测试输入。未读取签名口令、私钥、私人网络日志或支持邮箱。

## 5. 注册查询的具体边界

### 5.1 输入、目录与真正发送值

- UI 接受域名或受支持公网 IP，不接受任意 URL/凭据作为查询。规范化使用本地规则；域名注册目标取 ICANN PSL 规则下的注册域，完整子域和原输入可在本地展示，但不是都发送到域名注册服务。PRIVATE PSL 部分不用于错误截断注册目标。E01。
- IP 查询发送规范化的公网 IPv4/IPv6，而非对输入 IP 进行反向 DNS 再代查域名。服务主机仍需系统 DNS；“不做目标 DNS/网站测试”不代表连接注册服务器完全不需要 DNS。E01/E03。
- IANA Bootstrap GET 不带查询值；会发送网络连接信息和固定 UA。公开目录缓存由三个地址族/用途 store 管理，内容为目录字节和抓取时间；不是查询历史或注册联系人缓存。刷新在用户这次动作内有条件发生，没有后台 180 天定时器。E02。
- WHOIS 已有已核验 TLD 可直接查询；服务发现时发 TLD 给 IANA，公网 IP 引导可发完整 IP，再在受限 IANA/RIR 链中继续。ARIN 的 `+ n` 是查询格式，不是额外用户身份。E01/E04。

### 5.2 明文范围与网络元数据

RDAP 使用 HTTPS，保留系统 TLS 信任和 URL 主机名校验；服务端知道查询 URL 和连接源信息。DNS、代理、VPN、运营商或沿途路由器能观察的具体内容不同：不能说 HTTPS 的 URL 路径对所有沿途节点公开，也不能承诺它们都看不到主机/端口/时序等元数据。

WHOIS 的请求行、查询域名或 IP、转介响应和原始登记响应在 **TCP 43 应用层没有 TLS**。直连时沿途可见；HTTP 代理 CONNECT 只提供隧道，不会自动加密隧道内 WHOIS。代码中供 ProxySelector 使用的 `https://服务:43/` 合成 URI **不是 WHOIS TLS URL**。VPN 是否保护某一段由实际环境决定，不能把它写成端到端加密。E03/E04。

注册响应可能有登记组织、联系信息、地址、电话、邮箱或条款文字，属于接收的数据，不是 App 自动从手机读取联系人并发送出去。当前结构化展示不应推断缺失字段；原始复制仍可能包含这些内容。维护者应把“公开记录可能含个人信息、复制前检查”列为披露审查内容。

### 5.3 Fake-IP、保留与日志

- `198.18.0.0/15` 映射只在授权注册服务的 transport 路径处理；没有把 Fake-IP 当作真实注册对象，没有新增代理厂商接收方，也不识别具体代理软件。
- 系统 HTTP 代理可能是本地地址；它是路线而非注册机构身份。域名、TLS SNI/校验仍以选定服务为准。不能宣传为绕过 VPN 或绕过 TLS。
- RDAP 最多 4 次 HTTP 请求/3 次重定向、总预算 20 秒；WHOIS 总预算 15 秒/最多 3 服务，并限制响应字节。有限请求不是后台追踪或服务端短期留存的证据。
- `RdapResult` 的 `rawRdap`、`whoisText`、`whoisSteps` 在内存；ViewModel 没有 HistoryRecorder/数据库/原文文件写入依赖。页面退出和 Activity 正常停止路径会 stop；配置变化可保留 state。内存不是保证立即擦除，也不保证服务端 ephemeral。
- 默认 RDAP observer 为 NONE；事件模型只记录阶段/类别/数量，不提供原查询/地址/代理/异常全文字段。本次普通生产日志检索未见注册原响应或联系人日志。QA evidence observer 不等于正式 App 自动日志上传。
- 功能内已有双语披露，但主要位于展开的过程详情（RdapScreen 192 行）。是否需在查询前更醒目说明明文与接收方，由维护者在 User Data/披露体验审查中决定；本轮不移动 UI，不武断宣布已满足所有显著披露要求。

## 6. LAN、Wi-Fi、标识与本地持久化

### 6.1 LAN 请求不是云上传，但确实跨越手机边界

扫描只向当前范围内目标发送发现请求，并在已发现主机上进行有界补充。NSD 使用系统服务，UPnP 的 LOCATION 校验要求数值 host 与响应源 IP 相同，拒绝用户名/密码、片段及 host 不匹配，不跟随任意外部图标/控制 URL；XML 对外部实体/DOCTYPE 有拒绝防护。NBSTAT 只发通配查询，SSH 只读取初始 banner，不认证、不执行命令。E11–E14。

仍应特别披露 PTR：`AndroidReverseDnsResolver` 使用系统 canonicalHostName，源码明确不绑定捕获网络，可能把私网反向名称交给配置的外部解析器。物理 LAN 绑定、系统解析器和 VPN 是不同路径；不能笼统承诺“所有 LAN Scanner 流量均不离开路由器”。这不是新增整份设备清单上传接口。

普通生产 C0 host enrichment 将 HostRecognitionResult 写入当前显示设备，`syncProfile=false`；NBSTAT 跳过 UNIT_ID，不把它提升为 MAC/身份，SSH 仅抽取受限 software token。既有 PTR/mDNS/UPnP 采用名称、厂商型号和协议标识可通过观察更新已有资料。应分别看待“本次内存线索”“数据库可选字段”“本次实际赋值”，不能从 Entity 存在字段反推全部报文已长期保存。

### 6.2 Wi-Fi 与网络信息

访问附近 Wi-Fi 需 Fine Location 与 Location Services 等系统条件；没有发现 GPS 坐标读取、GPS 历史或定位 SDK。Wi-Fi API 获得的 SSID/BSSID 仍是网络标识，可能间接关联位置，不能因此说没有任何敏感网络数据。

进入 Wi-Fi 页先读取系统缓存/当前连接、注册观察者；手动刷新才调用 `WifiManager.startScan`。内存 repository 无独立数据库/History；离开注销观察/扫描回调。Home 使用共享 NetworkContext，可在已有授权下读 SSID并随网络变化更新，不额外申请 SSID 权限或启动附近扫描。E16/E17。

没有证据表明 SSID/BSSID/AP 列表、RSSI、信道或 Wi-Fi 搜索文本被上传位置服务、LanYun Studio 或外部厂商。系统自身的 Wi-Fi 服务行为不是仅凭 App 源码可证明的“永不联网”。

### 6.3 保存、删除与日志

- Room 当前数据库版本 5，库为应用私有 `networktoolbox.db`；没有额外数据库加密工厂。依靠 Android 沙箱不等于数据已额外加密。E18。
- History 表保存时间、类型、title/summary、detailJson。LAN History 只冻结发现完成时的范围、计数、时长、每个 IP/本机网关标记/延迟/发现方法；后到名称/识别不回写旧 History。不要把已保存资料表混同于 LAN History。E20。
- 设备资料可保存 IP、可用 MAC、主机/mDNS/UPnP 名称、协议身份、网络 scope、型号厂商、手动类型/名称/备注、收藏及 WoL/first-last-seen。scope 哈希不是匿名化证明；备注可由用户输入个人信息。没有代码据此把它们发送注册机构。E19。
- **清除 WoL 只更新 wol 字段并保留原身份/观察行**（RoomFavoriteDeviceRepository 139–147）；即使该行原来仅有 WoL 用户设置，也不在此操作删除。其他编辑清空所有 managed state 的路径可能删除资料。政策“仍含用户管理设置时保留”不足以准确解释该差别，应作最小澄清，不能承诺“清空 WoL 就删除设备资料”。
- 本地历史/资料无自动日期过期；清空 History 不清资料/文件/剪贴板/支持邮件/第三方日志，取消收藏也不保证全部删除。Android 清除存储/卸载是另一个边界；不声称法证安全擦除。
- UPnP logger 注释虽称 debug-only，当前 `Log.d` **没有 BuildConfig.DEBUG 门禁**。实际字符串可包含 IP、截断 LOCATION 路径、网络身份和错误；query/fragment/userinfo 不进入 safe location，但路径仍可能识别服务。mDNS 日志主要是 generation、类型、状态/错误。它们是本地 Android 日志，没有上传 SDK/接口；不要称“Release 完全无日志”或把支持者手动分享日志视为自动收集。E15。
- Manifest `allowBackup=false` 不能证明所有 OEM 设备间迁移都不传数据；现有政策已有保留限定。本轮未开启备份或导出真实数据库。

## 7. 报告、文件、元数据和接收应用

### 7.1 三种不同输出，不共用一个匿名化结论

| 输出 | 实际默认内容/脱敏 | 保存与传输边界；证据 |
|---|---|---|
| 自动网络诊断完整报告：Copy/TXT/Markdown/PDF | 包括时间、结论/建议/检查、地址/prefix、网关、DNS/Private DNS、VPN/validated、目标/原始技术值；旧 schema rawData 可含未知 key。**不是全字段脱敏报告** | 同一冻结 presentation 生成；不重新采集/分析。Markdown 转义特殊符号，防下游意外远程图片/链接，但不是隐私擦除。E21/E24 |
| Website/TLS：新 Copy/TXT/MD/PDF | whitelist 导出：去数值连接/DNS地址、本地 DNS/代理标识、证书 Subject/Issuer/SAN、自由文本/原始 headers 等；URL 仅保留允许的公开 host/port/scheme，path/query/fragment 省略并标记 | 保留公开目标名、结果、端口、时间、耗时、TLS 协议/证书有效期等，仍可识别服务。`publicHost` 是语法/保留后缀规则，不证明域名绝对不关联个人或内部使用。E23 |
| RDAP/WHOIS 复制字段/原始响应 | 复制用户选定的字段或整段原始文本，**没有套用 WebExport 的白名单脱敏** | 系统剪贴板可能含注册联系人等；当前无专用注册结果 TXT/MD/PDF、自动 History 或自动邮件上传。E05 |

Website/TLS **History 不是新导出文件**：原本持久化移除 query/fragment，但仍保留 encodedPath、公开/私有目标、DNS候选地址、证书和网络环境。新导出更严格，不能反推已经保存的 History 也已被同样清洗，或升级后旧报告已自动匿名化。请求时 query 仍发目标，导出删掉不撤回已经发出的数据。E06/E22/E23。

### 7.2 文件生成、缓存、SAF 和分享

- TXT/MD 为 UTF-8，本地构造字符串；PDF 使用 Android PdfDocument/Canvas 和系统字体，不调用在线转 PDF 服务。没有在 renderer 设置用户姓名、设备序列号、GPS/EXIF 或隐藏原报告 JSON 的代码。PDF 底层系统可能附带生成器/创建信息，本轮未生成新文件/作二进制元数据验证，因此不作“没有任何元数据”的绝对承诺。
- Web 文件名为 `LinkBeacon-Web-{随机UUID}.{txt|md|pdf}`；不含目标/设备名。正文仍含导出/原始观察 UTC 时间及公开目标信息。自动诊断文件名含报告时间、正文含网络信息；不是用户名/设备标识命名，但时间仍有关联价值。E23/E24。
- WebExportViewModel 仅冻结投影和输出字节，不注入 Engine、Analyzer、History；SavedStateHandle 存请求 ID/格式/语言/状态，不存原始报告字节。进程死亡后缺字节则过期，不自动重新检测或上传。Text/PDF 的保存恢复同样处理冻结字节，不借恢复再跑诊断。E23/E25。
- **Save** 通过 ActivityResultContracts.CreateDocument 和 `ContentResolver.openOutputStream(uri)` 写用户选择的 URI。提供方可为本机存储或云盘，App 没有限定 local-only；不能仅凭“没有网络上传代码”就保证用户选的提供方不上传。
- **Share** 先在私有 `cache/reports` 写文件，经 FileProvider 的受限路径给出 `content://`、MIME、文件名与 `FLAG_GRANT_READ_URI_PERMISSION`，由 Sharesheet 的用户选择流程交给接收应用；provider `exported=false`，不是公开整个数据库/任意文件目录。接收应用可能保留/转发，当前代码不能知道最终全部接收方或其留存。授权启动不等于接收方已成功读/删。
- Web 与自动诊断 TXT/MD 使用独立 UUID 子目录，后续同类写缓存时清理超过 24 小时的合格旧文件；**不是到时自动运行的删除任务，也不保证 24 小时后文件已消失**。旧自动诊断 PDF 路径在下一次 PDF 分享时清理根目录旧 PDF。不能把两套缓存保留写成统一固定 TTL。系统也可清缓存；外部导出不受这类清理控制。E25。
- **Copy** 使用 plain text ClipData；当前没有单独敏感标志/应用自动清剪贴板逻辑。App 不自动上传剪贴板，但 Android 和获准软件可能处理/同步，不能宣称复制后只属于 App。注册原文和完整诊断尤其需要用户审阅。
- 没有 automatic recipient、预填完整诊断邮件或 developer upload endpoint。用户主动选择第三方仍有实际数据转交；Data Safety 的适用例外须按第 9 节独立审查。

建议的最短说明骨架（需另行双语审阅）：

> 注册查询会向 IANA 和所选注册服务发送规范化的注册域名或公网 IP 及必要连接信息。RDAP 使用 HTTPS；WHOIS 使用明文 TCP 43，查询与响应可能被网络路径观察。注册查询不自动保存为 History，结果在内存中展示，公开目录可本地缓存。原始响应可能含联系信息，复制前请检查。该操作不会自动发送家庭设备清单或诊断历史。

> 局域网识别还可发送受限 NBSTAT 节点状态请求和读取 SSH 初始标识，不登录或执行命令。TXT、Markdown、PDF 和复制/分享由用户触发；不同报告保留的网络细节不同，文档提供器或接收应用可能独立保存/上传。清除 WoL 配置不等于删除设备身份与观察记录。

这些骨架不取代现有完整的接收方、用途、保留、删除、权限、字体及支持邮件条款。不得因为“没有 App 后端”删掉第三方处理说明，也不要把新增注册查询表述为自动上传家庭 LAN 数据。
