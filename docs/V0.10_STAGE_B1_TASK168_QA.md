# Task 168 — isolated host/service recognition QA

Date: 2026-10-25. Base: `640ba2747d38f95cee129682e362ab9eedbf0b45`,
`codex/v0.10.0-stage-b1`. This is an experiment, not production activation or a
release gate. Private captures, authorization, APKs and detailed logs remain in
ignored `build/task168/`. Public results use anonymous inventory IDs only.

## Implementation and authorization

- Opt in with `-PrecognitionQa`. Only the debug source set receives
  `recognitionQa`, `recognitionQaCore`, the reviewed `nbstatTest` implementation,
  and the private `build/task168/authorization/scope.json` asset. Application ID
  is `com.networktoolbox.task168`; the QA manifest replaces the ordinary launcher
  with `RecognitionQaActivity`. No production scanner navigation is exposed.
- The pinned asset contains exactly T03/T05/T06/T09. The captured local address is
  excluded; current Wi-Fi/Ethernet, prefix, active Network and VPN policy are
  checked. Existing discovery runs on individually validated single-address ranges,
  never on the intervening addresses or the whole subnet. Its reachability/TCP
  evidence, fallback ports, timeouts and online decision are unchanged.
- The original `LanScannerViewModel`, C0 bridge/physical system-name executor,
  Network Lease, default mDNS/UPnP enrichers and `LanRecognitionPresentation` are
  reused. Shared-source windows are unchanged. New experiments begin after C0
  actually settles, not after a timer pretending that work has completed.
- One small shared presentation API, `configureQaDiscoveryAdmission`, permits a
  sparse C0 admission set before the first scan. It copies and bounds the set and
  requires membership in the current range. It does not select discovery targets:
  the paired QA `RunLanScan` independently enforces the private allowlist. Ordinary
  callers do not invoke it and still admit their full selected range.
- Experimental evidence is a transient QA overlay with distinct source labels.
  It is not encoded as an existing reverse-DNS/mDNS source and never enters identity
  matching or Room. Custom Name and existing automatic display names take priority;
  conflicting experimental names remain details only. SSH is service evidence,
  never a hostname, OS, hardware type or authenticated identity.
- The QA owner uses no History/Profile persistence repository. There is no
  change to production History freeze, StrongMatch, First/Last Seen, Favorite,
  Notes, manual type or WoL behavior. Formal app data is neither read for scoring
  nor cleared/overwritten. No account or server configuration is changed.

## Per-round source budgets

| Source | Eligibility / transport | Application budget |
| --- | --- | --- |
| NBSTAT | Discovered authorized remote targets; captured-Network UDP137 unicast; original `NbstatExchange` and strict `NbstatProtocol` | One send/target, 500 ms receive, no retry |
| SSH identification | T06, or an authorized discovered target with current TCP22 success | One TCP22 connect, 250 ms connect + 600 ms absolute read window; 2 KiB, 255 bytes/line, at most 8 preamble lines; no client data/authentication |
| System PTR | Authorized discovered target still without an automatic name | One captured-Network `DnsResolver.rawQuery`, 1000 ms deadline; NO_RETRY, NO_CACHE_LOOKUP, NO_CACHE_STORE, CancellationSignal |
| Reverse mDNS PTR | Authorized discovered remote T03/T06 | One legacy one-shot query, 800 ms receive, at most 32 datagrams of 4096 bytes; no retransmission |

The maximum new-source concurrency is two; a per-generation claim set prevents
duplicates. Socket I/O uses a fixed two-thread process owner, with no replacement
pool on cancellation; its queue is bounded to 16 entries. Stop/network invalidation closes registered resources,
cancels pending work and rejects late evidence. Framework DNS callbacks use a
stable non-rejecting executor. A whole-round 30 s failsafe includes C0. Per-source
failures do not cancel unrelated sources.

System PTR follows the captured network's actual resolver/Private DNS configuration;
the configured servers are not described as proven responding servers. There is no
direct-cleartext experiment, guessed gateway, public fallback, PTR-target connection,
cache insertion or persistent hostname key. API submission counts are not packet
captures of Android's resolver or proof of upstream forwarding behavior.

Reverse mDNS uses an ephemeral source port to the standard link-local multicast
destination, outgoing IP TTL 255, and the captured interface. It neither binds nor
joins port 5353 and does not change the existing NSD service catalogue. Replies
must be same-subnet IPv4 from UDP5353 with the matching ID, question and PTR owner,
authoritative response mode and no cache-flush bit on accepted legacy records.
The decoder bounds counts/lengths/compression; duplicates merge at minimum observed
TTL, zero TTL withdraws the value, and different names remain conflicting evidence.
Returned TTL is recorded as a snapshot, not a renewable cache or durable identity.
Same-link UDP observations remain unauthenticated; remote response IP is not a new
online device or identity key.

References: [RFC 4253 §4.2](https://www.rfc-editor.org/rfc/rfc4253.html#section-4.2),
[RFC 6762 §5.1/6.7](https://www.rfc-editor.org/rfc/rfc6762.html#section-6.7),
[Android DnsResolver](https://developer.android.com/reference/android/net/DnsResolver).

## Evidence limits and follow-up decision

This is a deliberately small, authorized live sample. A timeout is not a finding
that the host lacks the protocol. A negative system PTR answer describes this
network's current resolver result, not all possible DNS deployments. No proxy,
strict Private DNS, alternate router, hostile responder or server configuration
was introduced for this task. Positive system PTR and reverse-mDNS responses are
parser-tested; their positive real-device path remains unverified when this
sample returns no names. Unicode PTR names are conservatively rejected by this
ASCII-only experimental decoder, another potential information gap.

Existing C0 sources are allowed to finish and remain displayed through the
existing B1.1 mapper. In this live sample they yielded no usable baseline name;
therefore this is not proof of positive mDNS/UPnP compatibility across other
devices. Existing regression tests and unchanged adapters/windows support the
non-regression boundary. Baseline resolver caching/provenance cannot be inferred
from the display name alone. New system PTR explicitly bypasses local resolver
cache without bypassing network policy.

The added adapters are a transient QA evidence overlay, not new production
source enums. This avoids mislabelling NBSTAT as reverse DNS or SSH as a host
name. The ordinary mapper is reused for existing sources; adding native typed
NBSTAT/SSH evidence to that mapper requires the next review. Custom-name and
conflict precedence are unit-tested. Formal saved profiles are not loaded into
this isolated package or used to improve the experiment's score.

Minimum next step, subject to a separate task: review typed session-scoped NBSTAT
name evidence and SSH service evidence with source/time/trust fields; adapt the
existing shared mapper; preserve user/custom/baseline precedence, admission,
lease and physical-resource budgets. Keep persistence and online evidence
unchanged. Do not enable a general banner scanner, WSD, SMB negotiation or HTTP
identification based on these results. No experimental source is activated in
the ordinary application by this task.
