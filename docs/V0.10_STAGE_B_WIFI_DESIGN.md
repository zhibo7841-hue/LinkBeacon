## 3. 最终信息架构：专业数据优先的同一页面

### 3.1 分区顺序

1. **Wi-Fi Analyzer / Wi-Fi 分析**：保持名称、返回路径和手动刷新入口。
2. **当前连接**：连接来源与可用状态、SSID、BSSID、RSSI dBm/原等级、频段/主信道。
   保留紧凑技术摘要；仅扩展字段折叠。未取得连接不阻止附近扫描区使用。
3. **扫描状态**：访问限制、本次请求阶段/失败、批次新鲜度/时间同时表达。
   状态说明默认可见，不放进知识帮助，不限额为“两条”，不只用 Toast。
4. **Networks / Channels**：继续同页切换，保留共享频段筛选；Networks 中保留搜索。
   两视图显示同一批次限定，不建“易懂概览/专家观察”双页或新导航。
5. **选定视图的数据**：Networks 紧凑 AP 卡片；Channels 按频段/主信道显示观测统计。
6. **按需的解释与依据**：通用知识放“说明与限制 / Explanations and limitations”；
   行内技术说明贴近相关字段。不要让长教程挤在列表前面，也不能折叠必要状态。

保持当前 Lazy 布局、独立列表滚动与 AP 展开；具体 Compose 布局/恢复键策略是候选。
不新增排序菜单、图表、自动测速、Copy/BSSID 功能或新的工具入口。

### 3.2 相对 Work 建议的取舍

- 采用单页，将主要技术数据与状态置于首层，详尽解释按需展开。
- **BSSID 默认可核查**，不是必须打开详情才能区分同 SSID AP；RSSI、频段、信道亦然。
- 不在当前连接上显示研究候选“Channel Width”；即使扫描中匹配了 BSSID，也不回填。
- 扫描 AP 的已观测宽度可放紧凑摘要；无值时明确未知，不能用连接速率推导。
- 不强制首屏最多两条知识卡片；0～2 条仅是可选知识摘要预算，不限制错误/缓存等必要状态。
- 验收重点是技术数据可核查、操作路径高效、事实可追溯和无障碍体验。
  用户研究用于优化体验，发布门槛仍以功能正确性和兼容性证据为准。

## 4. 字段级展示规格

“默认”表示该区域可见时无需展开，不是要求全部字段塞入首屏。
关键字段未知时保留标签和原因可达性；扩展非适用字段可以不设空行。

### 4.1 当前连接（只能来自连接快照）

| 字段 | 默认 / 展开 | 来源及规则 | 未知或不可用 |
| --- | --- | --- | --- |
| 当前连接状态 | 默认 | `ready` + `currentConnection` 与已知 Wi-Fi 开关；有效连接快照可表示系统报告 Wi-Fi 连接，不等于公网已通 | `!ready` 显示读取中；快照 null 本身不能区分断开/受限/读取失败，使用“未取得 Wi-Fi 连接信息” |
| SSID | 默认主行 | `currentConnection.ssid`；现有共享 NetworkContext 仅可作初始名称占位，不能顺带展示旧 RSSI/连接徽标 | “SSID 不可用”；不能将 null/UNKNOWN_SSID 硬称隐藏 SSID；无共享名称时不编造 |
| BSSID | 默认独立短行 | 连接快照规范化 BSSID，可完整核对 | “BSSID 不可用”；不展示 `02:00:00:00:00:00` 或全零，不推断真实 MAC |
| RSSI / 信号等级 | 默认 | `rssiDbm` / 现有 `signalLevel`；明确“系统连接信息”来源 | 有效值之外显示不可用/无法评级；不能 0 dBm、0%、最弱或满格 |
| 频段 / 主信道 | 默认 | `band` / `channel`，保留已有平台转换和纯映射 | 分别显示未知，不因某值未知连带猜另一个 |
| 安全类型 / 标准 | 紧凑默认摘要，长内容可换行 | 已提供枚举；不从 PSK 强行猜 WPA 代际；不是安全审计结果 | 不可用，不自动宣称开放/旧协议 |
| 频率 MHz | 展开 | `frequencyMhz`，连接级事实 | 不可用；不拿 AP 频率补齐 |
| Link speed | 展开，限定说明与值同现 | `linkSpeedMbps > 0`，仅已有单一协商链路速率；不是吞吐测试，也不是分向 Rx/Tx 保证 | 无有效值不显示 0 Mbps；写“未提供”或省略可选行 |
| Channel Width / center frequency | **不提供连接字段** | 当前 Raw/Domain 连接模型均无此事实 | 在按需限制说明注明未采集，不借 AP width、SSID、频段或速率估算 |
| 默认出口 / VPN | 有对应真实标志时默认短提示，细节可展开 | `isDefaultNetwork` / `vpnIsDefaultNetwork` | 未作为默认出口不是连接失败；不把底层 Wi-Fi 当 VPN 外的实际 HTTP 路径 |
| 连接采样时间 | 只显示来源限定，不伪造年龄 | 当前模型没有采样时间 | “采样时间未提供”；不是扫描时间、映射时间或页面打开时间 |

### 4.2 Networks：扫描 AP 观测

| 字段 | 默认 / 展开 | 来源及规则 | 未知或不可用 |
| --- | --- | --- | --- |
| SSID | 默认主行 | `ap.ssid`，保持 Unicode；同 SSID 多 AP 不合并 | 仅 `isHidden` 有证据时称隐藏 SSID；否则“SSID 不可用”。现有 `isHidden` 仅来自原始空 SSID，不能证明路由器配置或身份遮蔽原因 |
| BSSID | 默认 | `ap.bssid`；同 SSID 区分的主要核查字段 | 不可用；未知 BSSID 行保持独立，不能按 SSID 合并 |
| RSSI / 原信号等级 | 默认 | ScanResult 经现有规范化；来源为该行扫描观测 | “信号不可用”，不是低信号；缓存行用过去时语义 |
| 频段 / 主信道 | 默认 | `band` / `channel`；总是携带频段语境 | 未知；不混合跨频段同编号信道 |
| Channel Width | 默认紧凑字段 | `ap.channelWidth`，标“扫描宽度 / Observed width”；80+80 MHz 保留非连续含义 | “宽度未知”，不能默认 20 MHz，不能回填连接卡 |
| 观测时间 | 默认紧凑说明 | 该行 `observationTimestampElapsedMs`，独立于结果集最新时间 | “观测时间未知”；不能用批次最大时间替代每行 |
| 连接匹配 | 默认，仅为 true 时 | 原有 `isConnectedAp`；BSSID 与兼容无线事实匹配，不改 predicate | 无匹配不代表离线；同 SSID 不够；MLO 下只称匹配系统连接标识，不夸大为全部链路一致 |
| 安全类型 | 默认紧凑摘要 | `securityTypes`；保持现有不确定性与过渡模式 | 不可用，不猜协议或漏洞 |
| 频率 / 中心频率 0、1 | 展开 | 已有 MHz 值；两中心分别标识，不能同名串联让人误以为同一字段 | 未提供的可选中心频率不显示 0；不画新频谱图 |
| Wi-Fi 标准 / DFS | 展开 | 现有标准与 `WifiRadioMapper.isDfs` 标签，DFS 是映射说明 | 不声称雷达已探测、地区许可或信道可以切换 |

### 4.3 Channels：原有观察统计

| 字段 | 展示规则 |
| --- | --- |
| 频段、主信道、AP 条目数 | 默认可核查，来自现有 `WifiChannelObservationSummary`；计数包含匹配当前 AP 的观测，不擅自减 1 |
| 最强扫描 RSSI | 默认显示有值的 dBm；无值标未知；不是当前连接 RSSI、总功率、噪声底或信道质量 |
| 当前 AP 匹配标志 | 原有 `connectedApPresent` 才显示；不凭 SSID 推导 |
| 计数范围与时间 | 默认短注：“基于本批次已知主信道的 AP 观测；不受搜索影响”；同显批次缓存/错误状态 |
| 基本测量边界 | 默认短注“AP 数量不等于干扰或占用率”，完整知识解释按需展开 |
| 60 GHz / 未知信道 | 保留 Networks 中真实观测；不参与既有 Channels；解释排除范围，不静默改统计逻辑 |
| 频段为空 | 只有存在批次且访问/筛选语境足够时称“本批次未观测到”；不能称该频段空闲/不支持/最佳 |

不新增加权星级、射频重叠算法、信道负载、Channel Health 分数或 Best Channel。

## 5. 来源、时间、未知状态契约

1. **连接与扫描完全分源**：连接 RSSI 来自 WifiInfo，扫描 RSSI 来自 ScanResult。
   即便 SSID/BSSID 相同、数值不同也保留两份；连接时间未知不能被批次年龄掩盖。
   现代 MLO 中连接字段未必描述同一扫描链路；只标连接级观测，不新增 MLO 采集。
2. **时钟不混用**：单 AP 微秒自启动时间经当前规范化成为毫秒；年龄使用同一次启动的
   monotonic elapsed time。批次 `observedAtElapsedMs` 是读取时间，不是每 AP 最后观测时间。
   改墙钟、切语言、展开、返回页面不会把原时间变新。
3. **FRESH 是批次证据标志，不是永久“刚刚”**：复用现有 callback+时间推进判断，
   显示“收到更新 / Updated results”并配批次最新条目的真实年龄；不宣称独占本次硬件扫描。
   混合新旧 AP 各自保留时间，不把批次最年轻时间广播给所有行。
4. **无新阈值**：不重写 `WifiFreshness`，不定义新的 fresh 秒数、RSSI 分级或拥挤阈值。
   现有时间规范化允许读取时间后 1 秒容差；展示层若得到负年龄仍应注明时间不可确认，
   不夹零冒充刚观测。超出当前验证范围的值已被置空；不借此改 Core 校验。
5. **未知不归零、不猜原因**：缺失、未映射、无效、被系统隐藏在现有模型中不一定可分。
   统一“不可用 / Unavailable”或“未知 / Unknown”，技术解释写“系统未提供有效值，
   可能与访问限制或设备实现有关”，不能断言“用户拒绝”或“硬件不支持”。
6. **隐藏 SSID ≠ 身份遮蔽**：只有已有 raw 空名标记才有隐藏指示；null 规范化结果不够。
   即便已有 isHidden，也不把它升级为路由器配置证明。BSSID 不替换为设备真实 MAC。
7. **陈旧不等于消失/离线**：旧 AP 没有新观测，仅能描述最近可用快照，不生成 LOST/
   offline 状态、不刷新 Last Seen、不把扫描数当局域网在线设备数。
8. **范围可追溯**：连接、批次、单 AP、频段/信道的每条说明标清 scope；搜索为空是 UI
   过滤结果，不写入 Core。不持久化 SSID/BSSID，不发送解释、扫描或用户标识。

Android 依据：[WifiInfo](https://developer.android.com/reference/android/net/wifi/WifiInfo)、
[ScanResult](https://developer.android.com/reference/android/net/wifi/ScanResult)、
[扫描工作流](https://developer.android.com/develop/connectivity/wifi/wifi-scan)。
本项目字段是否存在以上述源码为准，不以文档中的新 API 反推已经采集。

### 6.2 排序与去重候选

状态顺序：访问条件 → 本次刷新阶段/失败 → 批次缓存/新鲜度/时间 → 数据/筛选空态。
可共存的状态不互斥。知识解释按字段关联展示；同 scope+code 的重复说明合并，
不同 AP、连接、批次的证据不混合。同一原因不在状态条和两张知识卡机械重复。
不引入全页 HEALTHY/WARNING/ERROR Wi-Fi 质量结论。

候选纯输出可采用 `code + typed arguments + evidence refs + scope + placement`
（status / field qualifier / expandable explanation），再由 presentation 本地化。
若附 action key，只指向现有手动操作，不执行动作。稳定顺序、具体类型名、文件位置
在 B2.1 评审；不要求通用规则引擎、反射框架或新依赖。

## 7. 关键交互状态与组合审查

| 输入状态 / 操作 | 必须呈现与行为 | 禁止行为 |
| --- | --- | --- |
| 首次进入，ready=false | 读取中；共享名称仅作名称占位；不挂旧信号/连接匹配；稍后按真实 snapshot 呈现 | 入页为解释额外触发扫描、自动授权或假造连接值 |
| 未主动 Refresh，有 Android 缓存 | 显示缓存/未知时间与已有 AP；允许现有条件下显式刷新 | 显示刚刚扫描完成 |
| Requesting/Waiting，有旧 AP | 真实请求进度+旧批次标签/原时间同时可见；现有单 flight 与 disabled 按钮 | 接受请求 true 就清空缓存、重置时间或显示新结果成功 |
| 启动拒绝+非空缓存 | 失败说明+缓存+原年龄；当前连接可仍为 -62 dBm 良好 | 失败被缓存标签吞掉；全页变网络错误 |
| Error/Restricted + lastBatch | 明确 issue/accessStatus，保留已可用旧数据的缓存限制；未知原因不猜 | 只读取 `batch.issue` 的两个分支、隐藏其他状态或清空为发现 0 个 |
| Waiting 到 15 秒无新结果 | 保留现有 Core 超时结果和缓存，停止等待 UI；“未收到新结果” | 延长等待、Timer 模拟进度、无限自动刷新 |
| 批次有更新但含旧 AP | 批次更新与每 AP 年龄分源；来源/time 未知时明确 | 每行都标刚刚或把系统广播写成本 App 独占扫描 |
| 权限拒绝/仅大致/永久拒绝 | 现有清楚说明与单次用户动作；有值的连接区域仍可核查 | 自动循环权限弹窗、增加 Nearby 权限或从缓存判断用户实际位置 |
| 定位关闭 / Wi-Fi 关闭 | 原始条件说明；旧批次仍标缓存；Wi-Fi 关闭不能留旧当前信号 | 自动开系统开关、把权限/开关问题称路由器故障 |
| 未连接或只取得部分连接字段 | 仍允许访问条件满足时的附近观察；不能分因则说信息不可用 | 以 null 断言已断网，或用扫描同 SSID 补当前卡 |
| 空批次 / 选定频段空 / 搜索空 | 分别说明可用批次未观测、该频段未观测、现有筛选/搜索无匹配；受限时语义降级 | 一律显示“没有网络”、宣称设备不支持或 AP 离线 |
| Networks↔Channels | 复用 batch、保留频段；搜索文本留存但只作用 Networks；已有限制两视图都可读 | 因切视图额外调用扫描/重算 Core 计数 |
| AP 展开、知识展开、语言/主题/字体变化 | 仅呈现变化，保留来源与状态，避免展开键/焦点转到另一个 AP | I/O、History/Identity/Last Seen 写入、自动重排算法或抹掉失败 |
| Wi-Fi→蜂窝 / AP 切换 / VPN 默认 | 按原观察者更新连接；旧 batch 不是新连接观测；真实默认出口/VPN 标志可见 | 改原 network/change 生命周期、跨网络补字段、诊断 VPN 故障 |
| 返回/后台/重建/权限设置往返 | 复用现有 enter/leave/reobserve；年龄由原时间重算，保留已有交互恢复契约 | 新增后台扫描、假定能恢复旧进程原始射频快照 |

已发现的展示不足仅作为后续 B2.2 目标：当前 null 连接文案、部分错误遗漏、FRESH
永久“刚刚”和关键 BSSID 默认可见性。若后续证明缺陷来自平台采集而非 presentation，
单列证据和变更评审，不能在解释任务中夹带改 Repository 或权限。

| W10 | 重复/多条解释、切语言、展开、筛选、搜索 | 结构化语义稳定；必要状态不受两条知识预算限制；主动扫描/权限/探测/存储增量为零 |
| W11 | VPN 默认但有底层 Wi-Fi、连接切换、旧 callback | 来源/默认出口限制不混；旧 RSSI 不挂新身份，无跨源补齐 |
