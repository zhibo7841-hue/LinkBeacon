# LinkBeacon v0.7.0 Release Readiness

Audit date: 2026-09-19 (Asia/Shanghai)

## Executive Summary

LinkBeacon v0.7.0 RC1 is **Release Ready**. The frozen signed artifact passed the
representative-device full regression on Sony XQ-AT72 / Android 12 / API 31,
including an in-place upgrade from the official signed v0.6.0 release without
uninstalling the baseline or clearing application data. No runtime source,
resource, manifest, runtime Gradle, Room, or matcher change was required after
RC1 was frozen.

## Formal Scope

- Conservative, evidence-first saved-device association.
- User Device Type with consistent Material-style icons.
- Local Device Notes.
- Truthful First Seen / Last Seen and Current / Last observed address semantics.
- Localized Device Detail and Device Center search presentation.
- Additive Room v4-to-v5 migration preserving existing local user data.

The frozen scope excludes SSL/TLS and Website Access Diagnostics, Wi-Fi
Analyzer, multi-network management, background presence monitoring, a new
identity system, and unrelated tools.

## Feature Complete

Device Center V2 implementation is complete. The structured identity outcome
contract, Device Type and icons, local Notes, First/Last Seen, current/last-
observed address presentation, type/notes search, retention behavior, bilingual
presentation, and migration path were implemented before RC preparation. This
task changes release metadata and documentation only; it adds no runtime feature.

## Migration

- Room database version: 5.
- Registered migrations: `MIGRATION_1_2`, `MIGRATION_2_3`,
  `MIGRATION_3_4`, and `MIGRATION_4_5`.
- No destructive migration is enabled.
- v4-to-v5 is additive and preserves profile IDs, identity/scope, IPv4,
  Favorite, Custom Name, Wake-on-LAN configuration, Last Seen, and History.
- New nullable profile fields remain null where old data cannot prove a value;
  migration does not fabricate First Seen.

Task 094 executed AndroidX `MigrationTestHelper` against the real v4 fixture
and completed an in-place application upgrade on Sony XQ-AT72 / Android 12 /
API 31. Both migration instrumentation tests passed, SQLite integrity remained
`ok`, and existing profile and History data survived. Device Type-only and
Notes-only retention, managed-profile First Seen initialization, and strong-
observation-only Last Seen updates were also verified.

## Identity Safety

- `SavedDeviceProfile.id` remains the only stable local profile key.
- Matching remains network-scope-first and uses the existing structured result
  contract: strong match, weak compatibility match, conflict, or no match.
- MAC and protocol conflicts block weaker address fallback.
- Hostname, vendor, model, Custom Name, Device Type, Notes, and user-entered
  Wake-on-LAN MAC are not identity evidence.
- No matcher, identity rule, profile key, detector, or discovery behavior was
  changed during RC preparation.

## Device Profile

- User Device Type and Notes remain user-owned local profile data.
- First Seen is created only for a managed profile formed from a reliable
  current observation; migration and editing never invent it.
- Last Seen changes only after a reliable strong observation.
- Current address and Last observed address remain separate presentation facts.
- Device Type-only and Notes-only profiles remain valid managed profiles.

## Internationalization

- English and Simplified Chinese remain supported in one APK, including Device
  Center cards, search, Device Detail, type labels, Notes editing, timestamps,
  and address labels.
- User names, Notes, addresses, identity evidence, and protocol values are not
  translated or used as locale-dependent identity.
- No language, locale, or application-language behavior changed in RC preparation.

## Representative Full RC Evidence

- Device: Sony XQ-AT72.
- Platform: Android 12 / API 31, the minimum supported Android version.
- Artifact: the exact frozen signed RC1 with SHA-256
  `F103DABAEB0E9CE27C9EC1AD55CC78907BCF0DEB64B9DAB253B09FC71D94DAA6`.
- Upgrade path: official signed v0.6.0 was installed first and populated with a
  real saved gateway profile, Favorite, Custom Name, Wake-on-LAN MAC/port, LAN
  scan, Ping, and History. RC1 was then installed with `adb install -r`; there
  was no uninstall or data clear between the baseline and RC1. Package
  `firstInstallTime` and `ceDataInode` remained unchanged while version advanced
  to `0.7.0` / code 7.
- Migration: the saved profile, stable repository identity, Favorite,
  `BaselineRouter` Custom Name, Wake-on-LAN MAC/UDP port, Last Seen, and History
  survived. The migrated profile correctly showed First Seen as not recorded,
  Device Type as unset, and Notes as unset. The Room v5 migration and SQLite
  integrity path were also exercised by the 2/2 on-device database tests.
- Device Type: unset, Server, and Other were saved and survived force-stop and
  reopen. Clearing the user type restored detected/generic presentation, and a
  later LAN scan did not overwrite a user-selected type.
- Notes: add, edit, clear, Chinese text in English UI, exactly 500 code points,
  and 501-code-point rejection were verified. Notes-only retention worked.
- Retention: Type-only and Notes-only profiles survived; a Favorite + Type
  profile remained after unfavoriting; clearing its final user-managed field
  removed it according to existing rules. Detection and observation timestamps
  alone did not permanently retain unrelated devices.
- Observation semantics: the migrated profile retained a null First Seen. A new
  managed profile created from a reliable scan used the real observation time
  for First/Last Seen. Opening details or editing Favorite, Custom Name, Device
  Type, Notes, or Wake-on-LAN did not manufacture an observation timestamp.
- Identity safety: strong match, weak compatibility, conflict, and no-match
  paths passed focused tests. Strong MAC/UDN conflicts did not fall back to IPv4;
  weak matches did not learn strong identifiers, update Last Seen, or overwrite
  user-owned data. The conflict fixture did not inherit Favorite, Custom Name,
  Device Type, Notes, or Wake-on-LAN state.
- Address truthfulness: a device found in the active scan displayed Current
  address; after process restart without an active scan, its saved profile
  displayed Last observed address. Historical addresses were not presented as
  current.
- Device Center and Detail: type icons, Custom Name priority, Favorite, Local
  Profile fields, First/Last Seen, address labels, Quick Wake, and layout passed.
  English `server`, Chinese `服务器`, raw Notes text, Search + Favorites, and
  All/Found/Not Found/Favorites filters behaved as designed.
- LAN Scanner boundary: a 254-address scan completed with 9 real scan results in
  19.1 seconds. The scanner continued to display only the current scan result;
  saved-profile presentation remained in Device Center.
- Network checks: Device Detail Ping and TCP Port Check completed successfully;
  Back returned to Device Detail at a useful retained scroll position. Quick
  Wake sent the configured packet without altering identity evidence.
- Surrounding regression: Home, Tools, diagnosis, and History passed. A complete
  network diagnosis produced one localized History record. Existing Ping, TCP,
  and LAN scan records remained readable after upgrade.
- Language and theme: English and Simplified Chinese Device Center/Profile UI
  passed; user names and Notes remained verbatim. Device Center, Device Detail,
  Type Picker, and Notes Editor passed light/dark checks without material
  clipping, overlap, or contrast defects. Back and scroll behavior remained
  usable through editors and network checks.

## Known Issues

- Existing migrated profiles may correctly display First Seen as not recorded;
  migration cannot prove their original first observation time.
- A saved device not observed in the current scan is not classified as offline.
- Weak address-only compatibility is deliberately conservative and does not
  promote identity evidence or refresh Last Seen.
