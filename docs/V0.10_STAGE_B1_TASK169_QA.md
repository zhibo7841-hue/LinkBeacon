## Classification contract

`QaCategoryMapper` is a pure, QA-only interpretation of the current mapper output
and current target's validated experimental evidence. No socket, resolver,
coroutine, repository, address enumeration or inventory lookup is available to it.
The owner keeps category, host name and service as separate transient fields and
serializes category/certainty/reasons independently in local QA results.

| Observed evidence | Category result | Boundary |
| --- | --- | --- |
| Valid, unambiguous NBSTAT workstation name | Computer / Suspected | A computer-like clue, never Windows, physical PC, desktop/laptop or server proof |
| Current typed UPnP `DEVICE_TYPE_REPORTED` / `PROTOCOL_DEVICE_TYPE` with explicit `InternetGatewayDevice:1` or `:2` | Network infrastructure / Confirmed | Explicit logical gateway self-report; not authenticated hardware or a router model |
| SSH/OpenSSH identification, TCP success, SMB/HTTP/IPP advertisements | Unknown category; service evidence retained | Neither port nor service establishes a host OS/category |
| PTR name, friendly/model/manufacturer keyword, arbitrary device-type text | Unknown | No keyword or inventory-based classification |
| Conflicting categories/workstation names or existing platform-declaration conflict | Unknown, reasons retained | Deterministic; no last-response-wins and no confidence escalation by duplicates |
| Old/unavailable session | Unknown | Current owner/lease boundary remains authoritative |

Confirmed describes sufficient **self-report evidence**, not identity
authentication or guaranteed physical form. Mobile and other broad category
values are reserved in the QA model, but this task adds no unsupported rule to
populate them. There is no automatic Server category. An isolated service role
is deliberately not promoted to a device class.

The explicit gateway type whitelist follows the standardized device descriptions
linked by [OCF's Internet Gateway Device specifications](https://openconnectivity.org/developer/specifications/upnp-resources/upnp/internet-gateway-device-igd-v-2-0/).
This consumes an already collected UPnP description; it does not send a new query,
change service catalogues, or contact another host.

## Presentation and user-data boundary

The existing QA list gains one optional category line: `Possible computer` for
Suspected, or a qualified `reported` label for an explicit category. Unknown is
not repeated in the compact list; details say `Category: unknown`. Details retain
the source/reason, evidence, observation time and software version. No scoring,
tutorial, extra settings, hardware brand/model or OS inference is introduced.

The category display helper accepts an explicit manual `DeviceType` first, using
the caller's label. It never mutates the automatic assessment or counts a manual
selection as an automatic success. Unit tests exercise every existing manual
type, including Other. The QA package does not load formal saved profiles, so
real saved user fields are neither used as truth inputs nor modified. Custom-name
precedence continues through the unchanged Task 168 name projection/tests.

Stop/network invalidation clears both transient categories and their baseline
evidence alongside experimental results. A new scan starts a new generation.
Classification never participates in eligibility for a new probe; the Task 168
request order, timeouts, source conditions and two-operation cap are unchanged.

## Production integration recommendation

There is a modest presentation gain: one reusable NBSTAT computer **candidate**,
with no added query cost. It is worth a separate, narrow production-mapper review
that keeps typed provenance, current-session/lease checks, manual-field priority,
and the explicit possible qualifier. It is **not** evidence for default confirmed
computer/server identification or OS fingerprinting. Before any positive explicit
category integration, add live qualifying self-report and conflict samples;
current gateway coverage is synthetic only. T05/T06/T03 require independent,
category-specific evidence to move beyond Unknown, not more guesses from names,
ports or software tokens.

No category rule is enabled in the ordinary application by this task. No commit,
push, merge, tag, release, Play action, PRODUCT_PLAN/DECISIONS update or scope
change was performed. HEAD stays at the recorded baseline; all work remains
uncommitted for maintainer review. Stop here; production integration requires a
separate task.
